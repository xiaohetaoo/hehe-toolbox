## 一、确认修复

### 🟠 R11-1 下载文件名剥掉前导点，隐藏文件被改名（已修）
- **位置**：`js/tools/net-tools.js` `safeNameFromUrl`
- **现象**：原实现 `raw.replace(/^\.+/, '')` 无条件剥掉开头的点。
  下载 `.bashrc` / `.gitignore` / `.env` / `.env.local` 会得到
  `bashrc` / `gitignore` / `env` / `env.local` —— 隐藏配置文件当场变成普通文件，
  用户拿到的名字与线上文件名不一致，且 `.env` 这类改名后还可能被误传/误提交。
- **实测**（`.tmp-r12/probe-name.js`，抽取真实实现）：修复前 `.bashrc → "bashrc"`。
- **修复**：只剥「纯点」（`.` / `..` / `...`）这种无意义形态，保留正常点开头名；
  仍剥尾部点与空格（Windows 不允许）。路径穿越防护不受影响（`%2F..%2F` 仍被挡）。
- **回归**：`test-safename.js` 新增 2 条用例（隐藏文件名保留 / 纯点回退默认名）。
  同时把该测试**从「手抄实现」改为「从源码抽取真实函数」**——原来那份副本在
  本次修复后会继续用旧逻辑判绿，属于「测副本造成的假绿」。

### 🟡 R11-2 硬件信息读取失败时磁盘卡片永远空白（已修）
- **位置**：`js/tools/sys-tools.js`（系统与硬件 → 磁盘用量）
- **现象**：`invoke(SYS.HW_INFO).then(...).catch(() => {})` 空 catch。
  WMI 被策略禁用、磁盘刚拔出等情况下，「磁盘用量」卡片一直空白 ——
  用户分不清是「还在加载」「这台机器没有磁盘」还是「查询失败」。
- **修复**：catch 里写明可读原因（`✗ 读取磁盘分区失败：…`），与项目里
  其它失败路径一致。**这是静默失败，不是崩溃**，故定为 P2。

## 二、判据错、代码正确（已回退，记录教训）

这一节比上面的修复更重要：**审查脚本自己的假设必须先被验证**。

### ❌ 误判 1：暗色主题按钮白字不可辨
- 初版判据假设「主按钮 = 主色底 + 白字」，算出暗色 9 套配色对比度仅 1.65–3.65，
  看着像重大视觉缺陷。
- 实际：按钮用的是 `--on-primary`（暗色下是深色，如 `#0D0D10`），不是白字。
  用真实变量重算，**18 个主题组合全部 ≥4.51，全部达标**。
- 教训：查对比度不能假设前景色，必须读真实变量。

### ❌ 误判 2：布尔偏好 `"true"` / `1` 被吞
- `.tmp-r12/probe-prefs.js` 显示 `normalize('updateCheckOnStart', 'true')` 返回 false，
  我判定为「用户设置被静默丢弃」并改了实现。
- 实际：`test-prefs.js` 的 **PS-3 明确锁定**「布尔项只认真正的 true」，
  注释写明理由——**写入侧必须存布尔值**，一旦允许 `1` 就算 true，
  JSON 里会出现 1，而别处任何 `=== true` 或 `if (v)` 的判断都会分叉
  （`1` 真、`'false'` 也真），同一份配置两种解释。
- 已回退，并在实现处补注释说明「这是刻意的严格语义，别再放宽」。
- 教训：**改逻辑前先看有没有测试锁着它**——这次是测试替我拦下了错误修复。

### ❌ 误判 3：hash.js 有 job 订阅但无清理守卫
- 扫描器根据「文件里出现 `on('job:` 但没有 `onCleanup`」判定泄漏。
- 实际：`unsub()` 在 try/catch 之后的第 119 行，无论成败都执行；
  扫描器的正则窗口没覆盖到。**安全**。
