# 剥注释必须保留换行（行号保真）

## 现象

`stripComments` 早先把整段块注释替换成**一个空格**，块注释内部的换行
全部丢失。后果不是"注释没了"，而是**行号漂移**：

- 一个 40 行的文件头注释会让后面每一行上移 39 行；
- 实测 `main.js` 剥完比原文少 **400+ 行**；
- `scripts/` 里有 28 个脚本的行号因此全部对不上。

而 `stripComments` 的唯一用途就是「在同一份文本上做断言」。
行号一错位，所有按行号定位的能力都会静默指错位置，而且**不报任何错**：
lint 基线的行级压制、白名单按行号索引、CI annotation 指到出错行、
报错信息里的 `file:line`。

## 实测方法

```js
const raw = fs.readFileSync('main.js', 'utf8');
console.log(raw.split('\n').length, stripComments(raw).split('\n').length);
// 修之前：6214 -> 5810   （差 404）
// 修之后：6214 -> 6214   （相等）
```

对全仓库每个 `.js` 做同样的比对，修前有 28 个文件不等，修后全部相等。

## 结论

- 块注释要被抹掉，但它**占的行必须还在** —— 用等量换行补位。
- 同时必须**保留一个分隔空格**，否则 `a/*c*/b` 会粘成 `ab`
  （两个标识符拼成一个，剥注释不能改动代码语义）。
  顺序是「空格在前、换行在后」：多出来的空格是行尾空白，不会把上下两行粘成一行。
- 未闭合的块注释同样按原换行数补位，否则尾部所有行都会消失。

这两条要求同时成立、互不冲突，但很容易只做到一个 —— 本项目历史上
先做到了「不粘连」却丢了行号，属于典型的「一半正确的实现」。

## 影响到的代码位置

- `lib/src-scan.js:47` `stripComments()` —— 修复点，`newlinesOf()` 补位。
- `scripts/test-i18n-coverage.js` —— 新增一条**逐行比对**的行为断言锁住它
  （只比行数抓不到"行数凑巧相等、内容却错位"的情形）。
- `scripts/lib/source-assert-scan.js` —— 依赖「行号保真」这个前提，
  用同一套下标去取原始行文本做报错展示。
- `scripts/source-assertions-baseline.txt` —— 行号是它的阅读线索，
  行号漂移会让这张表失去意义。
