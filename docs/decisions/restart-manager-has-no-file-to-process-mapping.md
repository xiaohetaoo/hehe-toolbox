# Restart Manager 拿不到「哪个文件被哪个进程占用」

## 现象

`RmGetList` 返回的是**一组进程**，不是「路径 → 进程」的映射。
即使一次注册了 200 个文件、查到 3 个进程，也无法知道这 3 个进程
各自占着哪几个文件。

## 实测方法

注册两个被不同进程独占的文件（一个记事本打开，一个 node 打开），
调 `Lockers()`。返回的 `RM_PROCESS_INFO[]` 里只有 `dwProcessId` /
`strAppName` / `ApplicationType`，没有任何指向输入路径的字段。
`RmGetList` 的签名里也没有「按资源聚合」的参数。

## 结论

- 界面上只能写「**有 N 个进程**占用了其中某些文件」，
  绝不能写「这 N 个文件被占用」——后者把进程数说成了文件数，而且文件名
  从头到尾没出现过。
- 精确到文件需要另一步（对每个文件单独注册后查询），但那样每个文件都要
  一次 `RmStartSession`，而系统上限是 64 个 session —— 大目录必然失败。
  所以产品上选择只报告进程，并把「想知道具体是哪个文件」引导到
  文件占用解锁工具的目录查询。
- 同一批里重复的进程要按 `pid + type` 去重合并，否则分块查询后
  同一个进程会被数两次。

## 影响到的代码位置

- `lib/dir-move.js:212` —— `LOCKED` 的文案与 advice，措辞「N 个进程」。
- `ipc/dir-acl-links.js:121` —— 分块结果的去重合并（按 pid+type）。
- `lib/rm-lockers.js:22` —— 顶部说明里「RmGetList 需要先用 dwSessionHandle 查里」
  的注释块，讲了为什么必须两步调用。
