# v0.6.8 —— 硬件加速编码 · 标签页保活 · 11 项可调设置

这一版让视频转码、压制、裁剪走**显卡硬件编码**（NVENC / Quick Sync / AMF），
不再把 24 个 CPU 核全跑满。检测到可用硬件时**默认启用**，失败时**自动退回 CPU**
且如实告知。

这一版有三块内容，可以分开看：

| 部分 | 一句话 | 详见 |
|---|---|---|
| 硬件加速编码 | 转码/压制/裁剪改用显卡，约 2 倍速，失败自动退回 CPU | 第一～八节 |
| 标签页保活 | 切走再切回来，输入和结果都还在 | 第九节 |
| 11 项可调设置 | 上限、默认值这些原先写死的数字，交给你调 | 第十节 |

## 一、之前为什么是 CPU

`ipc/media-ffmpeg.js` 里所有编码点都写死了 `libx264` / `libx265`：

```
转码（ffmpeg:convert）· 压制（ffmpeg:press）· 裁剪（ffmpeg:trim）
```

三处全是纯 CPU 软编码。本机实测（30 秒 1080p30，i7-14650HX + RTX 5070 Laptop）：

| 编码器 | 耗时 |
|---|---|
| `libx264 -preset veryfast -crf 23` | 5.5 s |
| `h264_nvenc -preset p5 -cq 30` | 2.7 s |

**硬件快约 2 倍**，而且不占 CPU。但这版没有简单地「把 libx264 换成 h264_nvenc」，
原因见下。

## 二、为什么不只是换个编码器名

实测发现一个必须处理的事实：**硬件编码器的质量参数与 x264 的 crf 不是同一个刻度**。
照抄数值会让文件**体积翻倍**：

| 参数 | 耗时 | 体积 | 画质（PSNR） |
|---|---|---|---|
| `libx264 crf23` | 5.5 s | 18.8 MB | 43.0 |
| `h264_nvenc cq23`（照抄） | 3.2 s | **38.6 MB** | 46.2 |
| `h264_nvenc cq30`（换算后） | 2.7 s | 17.9 MB | 42.5 |

而且不同内容的换算量不一样（在四种内容上实测）：

| 内容 | crf23 基准 | cq30 的体积比 |
|---|---|---|
| 密集噪点 | 18.77 MB | 95% |
| 真实照片 | 0.44 MB | 87% |
| 录屏（纯色+文字） | 0.11 MB | 114% |
| 合成渐变 | 1.22 MB | 146% |

所以**不存在一个通用的偏移**。本版的做法是取 `crf + 7`（crf23 → cq30）——
它是唯一一档在三种真实内容上都不明显膨胀的。合成渐变仍会膨胀到 146%，
那是硬件编码器对连续渐变的固有弱项（色带），不是参数问题。

**这是一个诚实的取舍**：本版承诺「更快、体积大致不变」，
**不承诺**「画质完全一致」。真实内容实测 PSNR 差 0~2 dB，方向不定（照片内容上硬件反而更高）。

## 三、默认开启，但如实显示

按你的要求「检测到可用硬件就默认开启」：

- 从没设置过 → 探测到可用硬件就自动使用（设置页开关显示为「开」，与实际行为一致）
- 用户显式关过 → 尊重它，一直用 CPU
- 本机没有可用硬件 → 开关置灰禁用（留着可见，让人知道功能存在但当前不可用）

设置页会显示探测结果，例如「可用：NVIDIA NVENC」或「本机未检测到可用的硬件编码器」。
**探测是真跑一次编码**（实测 961ms，之后缓存），不是读显卡型号猜的——
因为 `gyan` 的 build 把 nvenc/qsv/amf 全编译进去了，但没有 A 卡时
`h264_amf` 会直接报 `DLL amfrt64.dll failed to open`。

## 四、硬件失败时自动退回 CPU

探测通过只说明「这一刻能跑」。实际还有几种一定会遇到的运行时失败：
驱动在会话中途更新、显存被游戏吃掉、睡眠唤醒后 CUDA 上下文失效、
超过编码器分辨率上限（实测 `Width 5000 exceeds 4096`）。

这些发生时整批任务会停在那一个文件上，用户只看到「转换失败」，而不知道换编码器就能过。
本版的做法是**自动重跑一次 CPU 编码**，并且：

- 界面显示「压制中 · 已改用 CPU」，不让用户以为「硬件加速这么慢」
- 结果的 `encoder` 字段如实记为 `libx264`、`fellBack: true`，不冒报成硬件
- 完成语里写明「硬件编码 N 个，回退 CPU M 个」
- **只回退一次**：CPU 也失败就是真失败，不再重试
- **用户已取消时不回退**：否则点了取消，风扇反而转起来

真机实测（5000×5000 源，NVENC 报 `Width exceeds 4096`）：
自动改用 libx264，产出 4.11 MB 且**可正常解码**，界面收到回退通知。

## 五、真机验证（全程走真实 IPC + 真实 ffmpeg）

| 场景 | 结果 |
|---|---|
| 默认（未设置过） | `h264_nvenc` / `hw:true` / 48.4MB → 18.7MB |
| 用户显式关闭 | `libx264` / `hw:false` |
| 用户显式开启 | `h264_nvenc` / `hw:true` |
| 目标 H.265 | `hevc_nvenc` / `hw:true` |
| 硬件失败（5000×5000） | **自动回退 `libx264`，成功产出且可解码**，收到 `hw-fallback` 通知 |

所有产物都用 `ffmpeg -f null` 复核过可解码，不是只看「文件存在」。

## 七、顺手修掉的一个回归

给「视频裁剪」接入硬件加速时，`await videoEncodeArgs(...)` 插到了 `jobs.set(id, …)`
**之前**，于是调用方拿到 job id 时句柄还没登记 —— 点取消没反应。
`test-video-trim` 直接抓到了（`jobs 表里没有这个任务的可取消句柄`）。
已把 id/state/jobs.set 提到最前面，并新增 R6 断言把顺序钉死。

## 九、标签页保活：切走再切回来，东西还在

以前切换标签页再切回来，页面会**回到刚进入时的样子** —— 输入框空了、结果没了。
现在切回来看到的就是你离开时那一屏。

- **保的是整个页面**，不是只回填输入框。所以 JSON 格式化后的结果、正则匹配列表、
  已选文件列表、缩略图、滚动位置都还在。
- **后台任务仍会停**：切走就意味着不看了，跑着的长任务会停下（这是既有设计，没改）。
  已经跑完的结果不受影响。
- **保留个数可调**：设置 → 通用 → 「标签页保活个数」，1～10，默认 6。
  开得多的人可以调大，在意内存的可以调到 1。

## 十、11 项原先写死的数字，现在可以调

新增 **设置 → 工具默认值** 分区。这些值以前散落在代码里写死，改一次要重新编译；
现在改完立即生效，不用重启。

| 设置项 | 默认 | 范围 | 影响 |
|---|---|---|---|
| 剪贴板历史条数 | 200 | 50～1000（步长 10） | 历史记录保留多少条 |
| 单条剪贴板上限 | 256 KB | 16～4096（步长 16） | 太长的文本不入库，避免历史库撑爆 |
| 首页「最近使用」 | 12 个 | 0～30 | 设为 0 就整块隐藏 |
| 图片压缩默认质量 | 80 | 10～100 | 打开工具时输入框的初值 |
| 录屏默认帧率 | 30 | 10～60 | 打开工具时下拉框的初值 |
| 更新检查缓存 | 6 小时 | 0～72 | 多久内不重复请求 |
| 启动时自动检查更新 | 关 | 开/关 | 启动 8 秒后查一次 |
| 崩溃日志保留份数 | 5 | 1～20 | 最多留几份，超出的自动清 |
| 拖拽递归深度 | 8 层 | 2～20 | 拖文件夹进来时往下展开几层 |
| 拖拽文件数上限 | 3000 | 200～20000 | 一次最多收多少个文件 |
| 屏幕标尺最小长度 | 160 px | 20～800 | 标尺最短能缩到多短 |

设置页的控件由一张规格表自动生成（`lib/prefs-spec.js`），
**主进程和界面共用同一套夹取逻辑**，所以不会出现「设置页限制了范围、实际使用点照收脏值」。

## 十一、这轮修掉的三个缺陷

**1. 高危功能在占位卡里开启后，页面不动**

点开关 → 确认 → 能力确实开了（写进了配置），但页面还停在「该工具未启用」上。
根因是标签页保活把「原地重绘」当成了「切回来」，贴回了旧页面。
已用一个准确的判据区分「换页」与「原地重绘」。

**2. 保活淘汰时误清了当前页的定时器**

标签页超过保活上限时要淘汰最旧的。淘汰时不该再跑一次「离开页面」的清理 ——
那清的是**当前页**的定时器。表现是：开第 7 个标签时，第 7 个工具刚起来的轮询立刻消失。已修正。

**3. 剪贴板条数下拉框选不中想要的值**

步长原本是 50，想要「80 条」时下拉框里根本没有这个选项，
选了也静默失败（存进去还是 50），看起来像「改了没生效」。
步长改成 10，并让所有设置项统一对齐到步长网格。
