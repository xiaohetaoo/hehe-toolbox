# v0.9.3 —— 第十二轮审查修复

本版是第十二轮深度审查的落地：修复 4 项缺陷（防重入一组算 1 项），排查中另排除 3 处审查自身的误报。

## 一、修复

1. **HTTP 客户端「发送」无防重入（P2）**
   慢接口几秒才返回，连点「发送」会并发多个请求，后完成的覆盖先完成的 —— 响应区显示的 body 与状态行对不上（请求 A 的结果配请求 B 的状态）。已按项目统一约定接入 `ui.guard()`（并发第二次直接挡掉，任何出口都复位）。

2. **office.js 七处长任务无防重入（P2）**
   PDF 合并 / 提取页面 / 拆分 / 旋转、图片转 PDF、文档预览（LibreOffice 转换可达十几秒）、翻译 —— 七个长任务按钮都没有防重入。连点后果：并发跑两份 pdf-lib、对同一输出路径弹两次保存框、并发拉起两个 soffice 进程、翻译在 8 秒超时窗内返回顺序不定。同文件的 PDF 转图片与 Office 转换早有防重入标志，证明是漏写不是设计。七处全部接上。

3. **硬件编码无效 crf 的回退值与界面默认不符（P2）**
   `cqFor` 对无效输入返回 cq25（`CQ_MIN+CQ_OFFSET`），注释却写「按默认 crf23 处理」—— 界面默认 crf 是 23，应得 **cq30**。cq25 的体积比 cq30 大约 40%（模块头部的实测标定表）。触发面窄（正常调用总传数字），但注释承诺与实现不符本身就是缺陷。已对齐。

4. **局域网扫描列表可能没有本机（P2）**
   Windows 防火墙在「公用网络」配置文件下默认拦入站 ICMP —— 本机 ping 自己也可能不通，ARP 表也未必有自己。此时设备列表没有本机这一行，用户无法分辨「列表里哪个是我」。现在本机始终列出（标「本机」、排最前）；若 ARP/ping 已命中则合并来源、不重复。

## 二、审查中排除的三处误报

- **硬件编码 `\b` 边界**：怀疑 `h264_qsv_foo` 会误命中 `h264_qsv`，实测 `\b` 在下划线处不成立、拦截正确（是审查脚本里残留了旧断言版本）。
- **`mergeDevices` 返回空数组**：按错误签名传参导致（实际签名是对象参数），修正调用后暴露出上面第 4 项真缺陷。
- **CSS 191 个「工具零引用」类**：全部被 app.js 外壳（sidebar/titlebar/search 等）使用，无死代码。
