# v0.6.3 —— 拖标签时跟着一张页面缩略图

上一版能把标签拖出来，但过程中除了标签变半透明之外什么都没有——
观感是"拖了一下、松手后别处冒出个窗口"。浏览器拖标签会跟着一张页面缩略图，
它把"我正在搬运这个东西"讲清楚了，也给出了"松手会在哪里出现"的心理预期。

## 先量，再决定

要复刻这个手感，先得知道一次截图有多贵。实测 `webContents.capturePage`
截内容区（125% 缩放下 614×510 物理像素）：

| | 首次 | 预热后 |
|---|---|---|
| 整窗 | 213ms | 15ms |
| 内容区 | 33ms | **5ms** |

缩到 360px 宽后是 **14KB** 的 data URL。

结论：**在越过拖拽阈值的那一刻截一次就够了**，不必每帧重截——
拖拽过程中只是移动那张已经拿到的图。这样"只点了一下标签"的操作
完全不产生截图开销。

## 做法

- 越过 40px 阈值时调 `win:thumbnail` 截内容区，把结果放进一个
  `position: fixed` 的浮层
- 浮层 `pointer-events: none`——**这一条是必须的**：否则指针一进入预览区域
  就被它挡住，`pointermove` 的 target 变了、拖拽跟着抖
- 用 `transform: translate3d()` 移位 + `requestAnimationFrame` 节流：
  只走合成层、不触发重排/重绘。`pointermove` 每秒可达上百次，
  每次都写样式会让主线程忙于样式计算，反而拖不跟手
- 入场 `opacity 0→0.94` + `scale 1→1.02`，120ms——"被提起来的一层纸"
- 截图失败时降级成一个图标 + 工具名的小卡片，而不是什么都不显示
  （静默会让人以为拖拽没生效）
- `prefers-reduced-motion` 下不做缩放，但保留阴影与半透明——
  那是"提着"的语义，不是装饰

## 验证

**给 `test-tab-detach.js` 加了 5 条（G1–G5）**，用 CDP 真实鼠标事件，
走完整命中路径：

- G1 越阈值后出现浮层
- G2 里面**是一张图**（不是降级卡片）
- G3 `pointer-events: none`
- G4 `transform` 有值（跟着指针）
- G5 松手后隐藏

真实数据（探针实测）：

```
GHOST {"exists":true,"visible":true,"opacity":"0.94","hasImg":true,
       "hasFallback":false,"pe":"none",
       "transform":"translate3d(327px, 135px, 0px)","srcLen":15974,"w":245}
TRANSFORM2 "translate3d(367px, 190px, 0px)"   ← 再移动，跟着走
AFTERUP {"visible":false}                      ← 松手后隐藏
```

变异测试：

| 变异 | 结果 |
|---|---|
| 去掉 `pointer-events: none` | G3 红（`pointer-events=auto`） |
| 去掉 `transform` 赋值 | G4 红（`transform=` 空） |
