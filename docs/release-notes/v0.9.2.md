# v0.9.2 —— 第十一轮审查修复

本版是第十一轮深度审查（渲染层工具 + lib 纯函数 + 主题/布局一致性）的落地：修 2 个真实缺陷，并补齐一处测试自身的方法论问题。

## 一、修复

1. **下载下来的隐藏文件被改名（P2）**
   `safeNameFromUrl` 原来无条件剥掉文件名开头的点：下载 `.bashrc` / `.gitignore` / `.env` 会得到 `bashrc` / `gitignore` / `env` —— 隐藏配置文件当场变成普通文件，用户拿到的名字和线上不一致；`.env` 这类还可能因改名被误传或误提交。
   现在只剥「纯点」（`.` / `..` / `...`）这种无意义形态，正常的点开头名保留；尾部的点与空格仍会剥掉（Windows 不允许）。路径穿越防护不受影响，`%2F..%2F` 依旧被挡成单层文件名。

2. **硬件信息读取失败时磁盘卡片永远空白（P2）**
   「系统与硬件」页的磁盘用量块用了空 catch。WMI 被策略禁用、磁盘刚拔出等情况下，卡片一直空白 —— 用户分不清是「还在加载」「这台机器没有磁盘」还是「查询失败」。现在会如实写出失败原因。

## 二、测试方法论修正

`test-safename.js` 原来**手抄了一份 `safeNameFromUrl`** 来断言。副本与实现必然分叉：本版修掉「剥前导点」之后，副本仍是旧逻辑 —— 测试照样全绿，真实行为却还是错的。这就是「测副本造成的假绿」。
现在改成从源码抽取真实函数求值，测的就是线上跑的那份代码；同时补了 2 条隐藏文件用例把这次的修复钉住。

## 三、审查中排除的三处误报

这一节的结论和修复同样重要——**审查脚本自己的假设必须先被验证**：

- **「暗色主题主按钮白字不可辨」**：初版判据假设按钮是「主色底 + 白字」，算出暗色 9 套配色对比度仅 1.65–3.65。实际按钮用的是 `--on-primary`（暗色下是深色），用真实变量重算后 **18 个主题组合全部 ≥4.51，全部达标**。
- **「布尔偏好吞掉 `"true"`/`1`」**：曾据此改实现，被 `test-prefs.js` 的 PS-3 拦下——那条测试锁定的「布尔项只认真正的 true」是刻意契约：允许 `1` 就算 true 会让 JSON 里混入 `1`，与别处 `=== true` / `if (v)` 的判断分叉，同一份配置两种解释。已回退并在实现处注明「这是刻意的严格语义，别再放宽」。
- **「hash.js 有 job 订阅但无清理守卫」**：扫描器正则窗口没覆盖到，`unsub()` 实际在 try/catch 之后无条件执行，安全。
