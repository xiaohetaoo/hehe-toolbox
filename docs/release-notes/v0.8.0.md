# v0.8.0 —— 修「框选区域时屏幕变形」，以及 6 处高 DPI / 交互缺陷

这一版的核心是**区域截图在高 DPI 屏上的显示问题**，另修了 5 处会让工具直接不可用或静默出错的缺陷。

---

## 一、框选时画面变形 / 放大（用户报告，两个独立缺陷叠加）

用户反馈「框选区域时屏幕变形」，并提供了对比截图。排查后发现是**两个不同的缺陷**同时存在。

### 1. 画面整体放大 1.875 倍（v0.7.4）

`snip.html` 里 canvas 只有定位样式，**没有 CSS 宽高**：

```css
canvas { position: absolute; left: 0; top: 0; }
```

canvas 有两套尺寸，缺一不可：

| 尺寸 | 作用 | 本工具的值 |
|---|---|---|
| `canvas.width/height` | 位图（后备存储）像素 | 2563 × 1603（物理像素，保证清晰） |
| CSS `width/height` | 页面上占多少 CSS 像素 | **没写** |

缺 CSS 尺寸时，浏览器把位图的 **2563 当成 2563 个 CSS 像素**来显示，而窗口只有 1367 CSS 像素宽 —— 于是整幅画面放大 1.875 倍，只露出左上角。

CDP 实测（同一台机器、同一个全屏框选窗）：

| | 修复前 | 修复后 |
|---|---|---|
| `canvas.getBoundingClientRect()` | **2563 × 1603** | **1367 × 855**（= 窗口逻辑尺寸） |
| `canvas.width/height`（位图） | 2563 × 1603 | 2563 × 1603（不变，保持清晰） |
| 位图 / 显示 | 1.0（放大且模糊） | **1.8749 ≈ dpr**（物理像素 1:1） |

修法是给 canvas 补上 `width: 100%; height: 100%`。宽高**两个都要写** —— 只写 width 会让纵向被压扁，只写 height 会让横向被压扁。

### 2. 源图被非等比拉伸（v0.7.3）

本机缩放 187.5%、逻辑屏 1366×854，实测四个尺寸：

| 项 | 值 |
|---|---|
| 窗口 `innerWidth/innerHeight` | **1367 × 855**（比逻辑屏多 1px） |
| `devicePixelRatio` | 1.875 |
| canvas 位图（`inner×dpr`） | **2563 × 1603** |
| 源图（`screen.size×scaleFactor`，取整） | **2561 × 1601** |

旧代码把源图**拉伸到窗口尺寸**：

```js
ctx.scale(dpr, dpr);
ctx.drawImage(img, 0, 0, innerWidth, innerHeight);   // 按窗口逻辑尺寸铺满
```

- 横向系数 2563/2561 = 1.00078
- 纵向系数 1603/1601 = **1.00125**

两个方向拉伸比不相等 → 各向异性变形；且是非整数缩放 → 画面发虚。

修法：改为「画布坐标 = 物理像素」，源图 **1:1 贴合、不做任何缩放**，多出的 2×2 物理像素留在右下被窗口裁掉。顺带把马赛克取样的换算从 `naturalWidth/innerWidth` 改为 `DPR`（两者不等时会逐像素漂移，涂抹位置与鼠标对不上）。

> 100% 缩放下 `dpr=1`、窗口与源图尺寸恰好相等，所以这两个问题都看不出来 —— 只有 187.5%/250% 这类非整数缩放才显形，因此长期未被发现。

## 二、把「变形」变成可断言的数学

新增 `scripts/test-snip-dpi-map.js`（11 条），全部做了**变异验证**（把源码改坏必须报红）：

- 旧实现的横纵缩放系数必须**不相等**（这才是变形来源）
- 新实现两个方向系数必须**严格相等**（等比 = 不变形）
- 旧实现在右边缘累积约 2px 错位（= 画布比源图多的量）
- 画布必须覆盖源图且不超出 2px
- canvas 必须声明 CSS 宽高（宽高缺一不可）
- 位图是物理像素、CSS 是逻辑像素（两者必须差 dpr 倍）
- 源码断言：不得再按 `window.innerWidth` 拉伸、不得有顶层 `ctx.scale`、导出不得二次缩放

## 三、其余 5 处缺陷

### 1. 图片混淆：整个工具完全不可用

`run()` 第一行调用 `picker.files()`，但 `filePicker` 根本没有这个方法，当场抛 `TypeError`。用户勾好图、填好密钥、选好目录，点「开始处理」**毫无反应**，连 toast 都没有。

真机验证：修复后成功产出 `noise1_scrambled.png`，像素比对前 50 个点 **50/50 全部不同**（混淆算法确实生效，不是原样复制）。

### 2. 文件选择器丢字段：两个工具的核心功能半坏

`filePicker` 解构 `opts` 时漏了 `pickProps`，也没传给 `dropzone`。`zip-tool` / `archive-7z` 想传「能选文件夹」，实际拿到默认组合 —— **拖拽能用、点击不能用**。

### 3. Windows 不支持双模文件对话框

把 `file-unlock` 的 `directory: true` 改成 `pickProps: ['openFile','openDirectory']` 后，实测弹出的仍是**纯「选择文件夹」**。查 `electron.d.ts` 确认：

> On Windows and Linux an open dialog can **not** be both a file selector and a directory selector.

即这个组合在 Windows 上**静默退化成纯目录选择器**。改为在上层**分两次问**：先弹「选择文件 / 选择文件夹 / 取消」，再开对应的对话框。

真机验证：点「选择文件」→ 弹出「**打开**」文件选择器（有「文件名(N):」输入框）→ 选中文件成功加入列表 → 「查出占用它的进程」正常返回结果。对比修复前：弹出的始终是「选择文件夹」，文件选不了。

### 4. 视频截帧：取消也执行

把「用户点取消」当成「用默认目录」，照样截帧、往磁盘写一堆没要的帧，还在选择前就建了空目录。

### 5. 图片水印：扩展名说谎

WebP 输入按 JPEG 编码、扩展名却照抄 `.webp`（bmp/gif 同理），产出扩展名与内容不符的文件；单张失败原来只 `console.error`，打包版没有控制台等于完全静默。

### 6. ZIP / 7z 自动命名：切错目录

取目录只看 `/`，混用分隔符会切掉后半段；**完全没有分隔符时 `slice(0,-1)` 不是空串而是掐掉最后一个字符**，`a.txt` 得到 `a.t` 当目录。

### 7. CSV 导出 Tab 分隔错列

把分隔符拼进正则，Tab 分支拼出的是字面量「反斜杠+t」而不是制表符，含 Tab 的字段不加引号，整行多切一列。

- `package-lock.json` 里自身版本停留在 0.3.8（自 v0.3.8 起历次发版都未同步）。这与运行时行为无关，改动它会触发依赖图重算，故本次不动。
