# v0.6.4 —— 修四个多窗口遗留：偏好不同步、孤儿任务、监听泄漏、窗口同名

上一轮把标签做成可拖出的独立窗口之后，有四处只有真正用起来才会发现的地方
没跟上。它们都不是"新功能没做"，而是**旧功能在多窗口形态下漏了一半**——
现有测试一条都没覆盖到。

## 一、独立窗口不跟随语言 / 配色 / 主题

三个不同实例，同一个共因：这三项是**整个应用**的偏好，但状态所有权一直在
渲染层。主进程只被动接收渲染层的 `SET_*`，从来没有反向通道。

- **语言**：`SET_LANG` 只更新主进程 `uiLang` + 重建托盘；渲染层的
  `i18n.setLang` 只作用当前窗口。主窗切成英文后，已经打开的独立工具窗仍是
  中文——用户刚从这里拖出去，两秒之内看到两种语言。
- **配色**：`broadcastAccent` 只遍历 `auxWindows()`（标尺/贴图/截图标注），
  不含 `toolWindows`。换了主色，独立窗保持旧蓝。
- **主题**：`setThemeAttr` 写的是本窗口的 `data-theme`，`SET_THEME` 只改
  `nativeTheme.themeSource`——而 CSS 走的是属性，所以别的窗口完全没变。

修法是补那条反向通道：新增 `app:ui-prefs-changed`，`SET_LANG` /
`SET_ACCENT` / `SET_THEME` 三个 handler 写完之后各广播一次
`{ lang, accent, theme }`，各窗口收到后自己应用。`theme` 传的是**解析后的**
`dark`/`light`——`system` 由主进程解析一次，避免各窗口 `matchMedia` 时机
不同而给出不一致的答案。

**过程中的两个发现**

1. 通道表原先 **100% 是 invoke 通道**（渲染层 `invoke`、主进程 `handle`），
   18 个推送事件全是裸字符串，从不进表。新通道是纯推送，立刻撞坏了
   `test-channels-sync` 的 6c（"表里有 = 主进程 handle 了"）和 6f
   （"总数 = 注册数"）。

   没有放宽判据，而是加了显式声明 `PUSH_ONLY`，**并补了反方向断言**：
   声明为纯推送的，主进程必须真的在 `send` 它。否则 `PUSH_ONLY` 就成了一张
   免死金牌——挂一条没人发的通道进去，6c 与上面那条都不会红。

2. e2e 抓到一个只有端到端才能显形的**竞态**：`applyTheme()` 里的
   `store:get` 要两次 IPC 往返，广播完全可能在它返回**之前**到达。那时广播
   先把 accent 改对，随后那次（早于广播发出的）读取才返回旧值，把它盖回去
   ——用户刚在另一个窗口换的主色，在这个窗口上闪一下就退回旧色。

   修法是 `prefsFromBroadcast` 覆盖标记；同时保证用户在本窗口主动改主题/配色
   时解除标记，否则本地读取会被永久忽略（改了主题、重启应用还是旧值）。

## 二、关窗口不取消它启动的任务

`closed` 只把窗口从 `toolWindows` 里过滤掉，没有取消任务。于是：

> 独立窗里跑着 ffmpeg 转换 → 用户关窗 → 任务继续在后台跑
> → 之后每条 `job:stream` 都按 `send()` 的兜底逻辑发到主窗口
> → 主窗若开着同一个工具页，`JobPrefix.subscribe` 的「首次匹配即认领」
> 会把这个外来任务当成自己的：进度条乱跳、结束弹「完成」

而用户手里那个 `jobId` 已经随窗口消失，连取消都做不到。

**两层都修**：

- **任务归属**：`jobs` 换成 `lib/job-owner.js` 的 `OwnerJobMap`，`set()` 时
  记下发起者的 `webContents.id`。关窗时遍历并 `cancel` 掉该窗口的任务。

  为什么继承 `Map` 而不是给 20 多处 `jobs.set` 逐个补字段：漏一处就是一条
  静默的孤儿路径，而且以后新写的任务默认又会忘。收在 `set()` 里，调用点
  一处都不用改。

- **`send()` 的丢弃语义**：抽成 `lib/ipc-route.js` 的三档判据——
  没有调用者（托盘/定时/启动期）→ 回退主窗；调用者活着 → 发给它；
  调用者已销毁 → **丢弃，不回退**。

  第三档是关键：回退本是给"没有调用者"准备的兜底，用在"调用者已死"只会
  制造串扰。丢弃时留一行 `console.warn`，排查「进度条不动」时能立刻区分
  「没发出去」和「被丢弃」。

## 三、拖标签的三个 document 监听从不退订

`attachTabDragDelegation` 把 `pointermove` / `pointerup` / `pointercancel`
挂在 **document** 上，却不返回退订函数。而 `tabbarEl` 是 `buildShell()`
每次新建的元素——切一次语言就换一个新标签栏，旧元素上的 `__heheTabDrag`
标记随元素一起消失，于是新元素会再挂一次。

**切 N 次语言后，拖一次标签会发出 N 次开窗请求，用户得到 N 个独立窗口。**
`shellCleanup` 早就收口了 click / keydown 与 9 个 IPC 订阅，唯独这三个漏了。

顺带修同一处的时序问题：截图回包里判断「还要不要显示预览」用的是**当前**
`dragState`。若用户在等待期间松手、再重新按下另一个标签并拖出，新的一轮
同样满足 `dragState.out === true`，上一轮的截图会盖到这一轮的预览上。
降级卡片里的工具名读全局 `dragState` 时错的是**名字**——用户看到"图标对、
名字错"，比不显示还困惑。改成用 `const st = dragState` 抓住当轮快照。

## 四、所有独立窗口都叫「核核工具箱」

`BrowserWindow` 的 `title` 写死，`loadFile` 之后也没有任何地方设
`document.title`。开三个工具窗口后，任务栏与 Alt+Tab 里是三个同名条目，
只能靠缩略图辨认——而缩略图在小尺寸下根本看不清。

**两层都要设**，这层容易漏：主进程设了 `title`，但页面加载完成后 Electron
会把 `document.title`（`index.html` 里写死的「核核工具箱」）同步回窗口标题，
把主进程那次覆盖掉。

工具名从新增的 `lib/tool-names.js` 取——主进程读不到渲染层的注册表
（`js/tools/*` 是浏览器脚本，`require` 会立刻 `TypeError`），而给 100 多个
工具文件加 UMD 适配只为拿一个名字，不值得。

两张表必然有漂移风险，所以 `test-tool-window-title.js` 三个方向对账：
少一条、多一条、名字不同都红。

```
E2 收到语言广播后面包屑变成英文        Base64 编解码 → Base64 Codec
```

强制从中文开始。
