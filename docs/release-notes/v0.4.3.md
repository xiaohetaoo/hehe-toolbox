# 核核工具箱 v0.4.3

这一版只做一件事：**把工具页的正文翻译从 3 个文件推进到 6 个**，并把「域名清单」「设置页说明」这两处容易失真的地方改成自动对账。

没有新增工具，没有改任何功能逻辑。

## 工具正文的双语范围扩大了

v0.4.2 把 **102 个工具的名称和描述**全部翻了，但工具页**内部**的文案（按钮、提示、空状态、错误信息）仍然只有二维码和哈希两个工具是英文。英文用户点进去看到的还是整屏中文。

这一版新增四个：**EXIF 查看、截图标注、文本编解码（含 Base64 / URL / Unicode / HTML / Hex 五个工具）、三栏对比**。

| 文件 | 迁入条数 | 覆盖工具 |
|---|---|---|
| `qr.js` | 27 | 二维码生成 / 识别 |
| `hash.js` | 8 | 哈希校验 |
| `media/exif-view.js` | 7 | EXIF 查看 |
| `media/snip-tool.js` | 10 | 截图标注 |
| `text-codec.js` | 18 | Base64 / URL / Unicode / HTML / Hex |
| `diff3.js` | 31 | 三栏对比 |

合计 **101 条调用点**，覆盖 **11 个工具**（此前 3 个）。

取词方向仍然是反的——调用点写中文原文作键，中文模式直接返回字面量、不查表，所以**中文界面零行为改动**是结构上保证的，不依赖英文表写得全不全。

## 三处「会过期」的清单改成了自动对账

翻译这类活最容易出的错不是译错，而是**清单过期**：迁了新工具，但下面这些硬编码的地方没人想起来改，于是测试看起来全绿、实际已失真。

| 原写法 | 问题 | 现在 |
|---|---|---|
| 测试里写死 `['hash','qr']` | 每迁一个就要回来改，且它只校验「等于这两个」 | 从各文件解析出声明的域，再与表比对：缺域、孤儿域都红 |
| 测试里写死「二维码/哈希」两个工具名 | v0.4.0 只有两个工具的事实，早过期 | 改成校验「说明里提到了工具名称双语 + 明说其余仍为中文」两条本质要求 |
| 设置页说明写死「两个工具页」 | 用户看到的进度描述会一直停在旧口径 | 更新为实际范围；并新增「已迁移域数量」与说明的对账断言 |

## 迁移过程中踩到的三个坑

**1. 测试解析出的键与表里的键不是同一个字符串。**
测试在源码上跑正则，捕获的是**字面量的书写形式**（源码里 `'\\x 前缀'` 抓到两个反斜杠）；而英文表的键是 JS 求值后的**真实字符串**（单个 `\x`）。两者不对等，于是「调用点没有英文」和「表里有孤儿」两条同时误报。加了一层解转义才对齐。

**2. 域名的正则写窄了。**
`[a-z]+` 匹配不到 `diff3` 这个含数字的域名，报「没有声明域」——其实是正则太窄，不是代码有问题。

**3. 多行字面量的取舍。**
有两处文案在源码里写成 `'前半段…' + '后半段…'`。我先试过让解析器支持「相邻字面量拼接」，结果它把**后面不相干**的字符串也吞了（`</span>`、`%`、`-noexif.jpg` 全被拼进文案里）——因为 `+` 右侧不一定属于同一条表达式，靠正则判断这件事不可靠。

最后选择**改源码为单行字面量**，而不是把解析器变复杂。这两处文案本来也没必要拆行。
