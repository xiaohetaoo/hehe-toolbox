# v0.9.7 —— 路径语义与归档预检收口（R22 + R23）

本版是 R22、R23 两轮审查的落地，共 12 项修复。其中两处是**真实安全洞**，
共同特征是「**fail-open**」——出问题时不是拒绝，而是放行。

## 一、归档预检的两处 fail-open（安全）

### 1. 文件/目录同名冲突只查一个方向

`archive-guard` 原来只拦「先把路径登记成文件，后来又有条目需要它是目录」。
但条目顺序由压缩包作者控制，反着来就绕过去了：

```
[{name:'a/b.txt'}, {name:'a'}]        → 旧版：通过预检（错）
[{name:'a'},       {name:'a/b.txt'}]  → 旧版：才抛 FILE_DIR_CONFLICT
```

那种包会在解压到一半时写盘失败，用户看到「解压失败」而不是「包被构造过」。

现在双向都查（新增 `dirLike` 集合）。

### 2. 坏 size 被当成 0，绕过所有大小上限

```js
const size = Number(raw.size) || 0;   // 旧写法
```

`undefined` / `''` / `'abc'` / `NaN` / `Infinity` **全部变成 0**。于是单条与累计
上限检查形同不存在，而 adm-zip 解压时会按归档里**声明的真实大小** `Buffer.alloc()`
分配内存 —— 检查看的是 0，分配用的是真实值。

现在 fail-closed：只接受有限非负数，坏值抛 `BAD_SIZE`，负数保留 `NEGATIVE_SIZE`，
目录条目（不参与解压）允许没有 size。

## 二、Windows 路径语义

### 3. `C:` 与 `C:\` 是两个不同东西

- `C:` = **盘符当前目录**（危险，Windows 会解析成“当前目录”）
- `C:\` = 盘符根

但代码里到处有“剥尾部分隔符”的逻辑，一剥就混。后果：

- PATH 里已有 `C:` 时，会误判成“根已存在”，不加根
- `removeEntries('C:\')` 会把 `C:` 项也删掉

现在盘符根保留 `\`，普通路径才剥；`/` 统一成 `\` 再比较。

### 4. 三写法会加两遍

`C:\Tools` / `C:\Tools\` / `C:/Tools` 是同一个目录，但原来「先去重再 strip」，
三种写法各自算独立项。改成「先 strip 再按语义去重」。

### 5. 长路径前缀 `\\?\C:` 不被识别

`path-text` 的公共 `dirname`/`basename` 只认普通 `C:`。而 260 字符限制下长路径
前缀很常见：

```
dirname('\\?\C:\foo')  →  '\\?\C:'    （盘符相对路径，拼输出目录会拼错）
dirname('\\?\C:\')     →  '\\?\'      （更糟）
```

现在 `DRIVE_ROOT` 同时认两种形态。

### 6. UNC 共享根被当成普通路径

`dirname('\\server\share')` 走通用「最后一个分隔符」分支，返回 `\\server`
—— 但 `\\server` 是主机名，不是目录。现在 `UNC_ROOT` 让共享根返回自身
（保留输入尾部斜杠）。

## 三、数据质量（`|| 0` 同源问题）

### 7. 空字段被当成有效读数

`Number('') === 0`、`Number(' ') === 0`，而 `'abc'`/`NaN`/`Infinity` 又不是 null。结果：

- `hasSmart` 误判为“有数据”，但详情里什么都没有
- 温度显示 `0°C`
- verdict 甚至输出「累计读写错误 **Infinity** 次」

现在 `numOrNull`：只有数字或非空数字串且有限才保留，其余一律 null。

### 8. 只有启停次数被当成“没有 SMART”

`hasAny` 漏了 `startStop`：只有启停次数的盘 `hasSmart=true`，但 verdict 仍说
「读不到 SMART 明细」，自相矛盾。现已纳入。

## 四、界面与数据兜底

### 9. 快捷启动在坏数据下整页空白

store 里有 `null` 项或旧版缺 `target` 字段时，`it.target.length` 在第一张卡就抛，
**后续快捷项全部不显示**。现在跳过非对象项，字段统一兜成字符串；
删除时也跳过 null。

### 10. 快捷启动默认名带扩展名 / URL 带查询串

默认名用的 `/\.\w+$/`，实际匹配的是「点 + 反斜杠 + w」——`报告.docx` 不命中，
弹窗永远带扩展名；URL 还把 `?x=1` 带进名字。现在按最后一个点切、只切 `dot>0`
（保留 `.gitignore`），URL 先剥 `?`/`#`。

### 11. 快捷卡长 URL 顶出栅格

160px 窄格里显示 40 字符 URL，`.tc-name/.tc-desc` 没有断行规则，
无空格 URL 会横向顶出卡片、压到相邻卡。补 `max-width:100%` + `overflow-wrap:anywhere`。

### 12. 全坏数据时没有空状态提示

快捷项全是坏数据时渲染空网格，与「有数据但都是坏项」在视觉上无法区分。
现在先 filter 再判空，复用同一空状态。

## 六、明确没做 / 遗留

- 111 个工具页只做自动冒烟，**没有逐页人工点击**拖拽、右键菜单、系统文件选择器；
  视觉类（长 URL 卡片）用 CSS 规则 + 冒烟共同验证，没做像素级截图比对
- `archive-guard` 仍不拒「同名文件条目出现两次」（后写覆盖前写，不构成目录穿越，
  但会静默丢一份内容）—— 需产品决定
- `path-text` 不处理 `\\?\GLOBALROOT` 等设备命名空间
- `env-path` 不解析 PATH 里的 `.`/`..`（Windows PATH 通常不写这些形式）
- `main.js` 的 store 解析失败仍保留损坏副本后继续用空内存 store（上一轮确认的产品取舍）
