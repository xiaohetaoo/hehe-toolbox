# v0.6.6 —— 文件占用解锁真的能解锁了；修 17 处缺陷 + 21 个文件换行符

这一版有两件事：**新增「结束进程并解锁」**（此前只能查不能解），以及一轮
逐条复核出来的缺陷修复。另外顺手修掉了 21 个文件被编辑器改掉的换行符。

## 一、文件占用解锁：从「只能看」到「真的能解」

原来只查「谁占着这个文件」，查到了也没法处理——用户还得自己开任务管理器。
现在每个占用进程后面都有一个「结束它并解锁」按钮。

### 为什么不叫「强制删除」

用一个以 `FileShare.None` 独占打开文件的进程做对照，在锁持有期间逐个实测：

| 操作 | 结果 |
|---|---|
| `unlink` | 失败 EBUSY |
| `rename` | 失败 EBUSY |
| `truncate` | 失败 EBUSY |
| `open(r+)` | 失败 EBUSY |
| `copyFile` | 失败 EBUSY |
| **结束持有进程后 `unlink`** | **成功** |

Windows 上不存在「不解锁也能删」的旁路。号称"强制删除"的工具做的是同一件事
（杀进程，或装驱动内核级清句柄）。本项目不装驱动、不做进程注入，所以把手段
如实写成「结束占用进程」，并在界面上讲清代价，而不是包装成魔法。

### 安全判据（`lib/unlock-safety.js`）

允许结束的条件，全部满足才放行：

1. 不是本程序自己（杀了会中断正在进行的写盘）
2. PID 高于低号段（≤1000 几乎全是系统进程）
3. 进程名不在系统关键名单里（lsass / winlogon / csrss …）
4. 不是本程序的父进程链（否则连带把自己关了）
5. 不是系统服务（服务由 SCM 托管，杀了会被立刻拉起；应走「服务管理」）

**名单与 `PROC.KILL` 逐项对齐**，不另写一份——两份必然漂移，历史上出过。
`test-file-unlock-release.js` 的 UL1 做双向比对，少一项或多一项都红。

### 三步原子

新增 `file:unlock` 通道，一次调用内完成：

```
① 复核占用    重新查一遍，不采信渲染层的结论
② 逐个校验    pid 必须确实在该路径的占用列表里（防 typo 杀错进程）
③ 杀完再复核  实测有这几种"杀了也没解开"：句柄延迟回收、
              同文件被多进程占用而 RM 只报一个、杀软实时扫描（RM 看不到）
```

四类结果分别回给界面：`killed` / `failed` / `blocked`（被安全判据拒绝）/
`missing`（进程已自行退出）/ `stillLocked`（杀了但还锁着）。

真机验证时踩到一个空洞：持有者在查询之后自行退出，通道返回 `missing`，
而界面**一个字都没显示**——用户点了按钮，既没成功也没失败提示。
已修，四类结果各有说明。

### 还没做的（诚实记录）

- **问题 11 的剩余部分**：`av-convert` / `video-press` / `video-trim` / `target-size`
  四处的 `App.onCleanup` 注册在第一个 await 之后（那时已是新页面生命周期）；
  `subscribe({onCleanup:true})` 全项目零调用方；dir-move 主进程侧 `jobs.set` 取消登记。
- **`server:stop`**：原注释写「疑点，尚未复现」。本轮**实测证伪**——慢速客户端 +
  8MB 传输中 `close()` + 立刻同端口 listen：无 EADDRINUSE、旧传输完整收完、
  只有约 170ms 的 status 滞后。结论是**不改行为**（改成等 close 回调只为消除
  170ms 显示滞后，代价是点停止要等传输跑完，体验更差）。注释已改成实测结论，
  `test-static-server-stop.js` 把这个结论钉住。

## 三、真机测试发现的 4 处崩溃/异常

用 `dsh-computer-use-win` 插件对真实运行的进程做交互测试（103 个工具逐个打开、
真实点击、真实输入），发现并修复：

### 1. 「文件内容搜索」一打开就崩（渲染期 TDZ）

```
ReferenceError: Cannot access 'start' before initialization
```

把 `start` 从 `function start()` 改成 `const start = guard(startImpl)`
（防重入的正确写法）时，**按钮那一行留在了原处**。函数声明会提升，`const` 不会。

而 `js/app.js` 的渲染兜底只打一行 console 日志，用户看到的是「一用就崩」。

新增 `scripts/test-tool-render-tdz.js`。这个检测器写了三版才对：

| 版本 | 结果 |
|---|---|
| ① 声明行之前出现过这个名字 | 误报 100+ 处（函数形参、对象键、字符串、返回值全中） |
| ② 只认「读值」形态 | 仍误报——漏了关键区别：**闭包里的引用不崩**（`onChange: () => resultBox.innerHTML = …` 里 resultBox 声明在后面，但箭头函数是之后才执行） |
| ③ 只查 render 同步执行路径 | 误报 0，注入真崩溃必红 |

### 2. Base64 解码把浏览器英文异常直接给用户

中文界面显示：

```
⚠ 不是合法的 Base64：Failed to execute 'atob' on 'Window':
  The string to be decoded contains characters outside of the Latin1 range.
```

改为三种归因：粘错方向（含中文/emoji）、含非法字符、UTF-8 解码失败；
认不出时才附原始报错。测试 H7–H9，变异验证 6/6 红。

### 3. 标尺纵向拖拽被钳到 161

handler 两个方向都读了 `w`。已修为 `horizontal ? w : h`。

### 4. 框选 Esc 取消后卡住

见问题 9。

## 四、换行符回归（21 个文件）

编辑工具在写出文件时把 21 个文件的换行符从 LF 改成了 CRLF（1 个反向），
使 diff 从 **2479 行膨胀到 11524 行**。已全部还原成 HEAD 的原始格式：

```
还原前：63 files changed, 11524 insertions(+), 9422 deletions(-)
还原后：63 files changed,  2479 insertions(+),  384 deletions(-)
```

`git diff --stat` 与 `git diff --ignore-cr-at-eol --stat` 现在**完全一致**，
说明没有换行符噪音。
