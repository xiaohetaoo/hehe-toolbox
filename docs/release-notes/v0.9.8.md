# v0.9.8 —— 竞态收口 + 路径/归档语义加固（R24~R29）

本版是 R24 到 R29 六轮深度审查的落地，共 **62 项修复**。主线有三条：
**竞态**（旧请求晚到覆盖新状态）、**路径语义**（C: 与 C:\ 混用）、
**归档预检 fail-open**（该拒绝的地方放行了）。

## 一、竞态：旧请求晚到会污染新状态（11 处）

这类 bug 的共同形态：用户点开始 → 切走页面 → 切回来再点一次 →
**上一轮的 `await` 这时才返回**，把旧结果写进新界面，或误退新轮的订阅。

| 页面 | 症状 |
|---|---|
| 磁盘分析 | 旧扫描的速度/结果写回，进度条归零 |
| PDF 换文件 | 旧 PDF 覆盖新选的 |
| **压缩包预览** | 旧包清单显示在新包位置（按序号+路径双判才修准） |
| Office 预览 | 同上 |
| PDF 水印 | 旧任务的完成提示点亮新任务按钮 |
| 网速测试 | **保活复用回来页面永久失效**（`disposed` 不复位 → `run()` 静默 return） |

**网速测试这一处最典型**：上一轮加的 `disposed` 布尔量负责清理，但**保活复用时不复位**——
用户切回来点按钮，第一行 `if (disposed) return` 直接静默返回，工具看起来彻底坏了。
而简单复位会引入第二个 bug（旧轮结果写进新页面）。最终方案是**双判据**：
`disposed` 管"隐藏页不写界面"，`speedRunSeq` 管"旧轮不许碰新轮"。

## 二、路径语义：`C:` 与 `C:\` 是两个东西（4 处）

- `C:` = **盘符当前目录**（危险，Windows 会解析成"当前目录"）
- `C:\` = 盘符根

但代码里到处有"剥尾部分隔符"的逻辑，一剥就混。后果包括：PATH 里已有 `C:` 时
误判根已存在、`removeEntries('C:\')` 删掉 `C:` 项、
`dirname` 对 `C:\foo` 返回 `C:`（盘符相对路径，拼输出目录会拼错）。

另外补了两处：长路径前缀 `\\?\C:` 与 UNC 共享根 `\\server\share`
（后者原来 `dirname` 返回主机名，那不是目录）。

## 三、归档预检的两处 fail-open（安全）

### 文件/目录同名冲突只查一个方向

条目顺序由压缩包作者控制，反着来（先 `a/b.txt` 后 `a`）能通过预检，
解压到一半才写盘失败。现在双向都查。

### 坏 size 被当成 0

```js
const size = Number(raw.size) || 0;   // 旧写法
```

`undefined` / `''` / `'abc'` / `NaN` / `Infinity` **全部变成 0** —— 大小上限检查
形同不存在，而 adm-zip 会按归档声明的真实大小 `Buffer.alloc()`。
现在 fail-closed：坏值抛 `BAD_SIZE`，负数保留 `NEGATIVE_SIZE`，目录条目仍允许无 size。

## 四、`|| 0` 同源问题的另外两处

- **磁盘健康**：`Number('')===0`、`Number(' ')===0`，空字段被当有效读数 →
  `hasSmart` 误判、温度显示 `0°C`、结论输出「累计读写错误 **Infinity** 次」
- **剪贴板敏感判定**：纯小写 40+ 串被当 base64 密钥 → **sha1、长订单号会被当密钥删掉**

## 六、发布流程提速（约省 8 分钟）

CI 和 Release 都在重复跑同一批测试：

| 位置 | 优化前 | 优化后 |
|---|---|---|
| ci.yml「纯函数回归」+「断言数守卫」 | 236s + 238s（**跑了 2 遍**） | 236s + ~5s（守卫读日志） |
| release.yml「Run tests」 | 253s（无条件） | 条件跳过 |

**Release 的跳过是自动判断的**：必须同时满足「这个 commit 上有 CI 成功的 run」
与「该 CI run 的 head_sha 等于本次 tag 的 SHA」。任一不满足就**老老实实跑全量**。

这挡住了「tag 指向旧提交」的风险——版本号对得上但内容不同。另外保留
`FORCE_RELEASE_TESTS=1` 可随时强制全量。
