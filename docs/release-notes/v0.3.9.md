# 核核工具箱 v0.3.9

本轮仍然**没有新功能，也没有用户可见的界面变化**，全部是工程质量与可维护性改造。

两次改造的动机不同：第一次是「补上缺失的验证层」，第二次是「让验证层本身可信」。第二次更值钱——因为它修掉了**一处让检查静默失效的缺陷**。

测试断言 **1269 → 1270**（全绿），lint 保持 0 错，并新增了类型检查（0 错）。

## 最重要的一件事：一道检查的强度取决于谁用什么编辑器存过文件

项目里有个元测试，用来防止「源码断言越写越多、却没写清它在锁什么」。它靠一条正则识别「哪些变量装的是项目源码」：

```js
/^\s*(?:const|let|var)\s+(\w+)\s*=\s*(.+)$/
```

问题出在 `(.+)$`：**点号不匹配 `\r`**。而仓库里 154 个文件是 LF、73 个是 CRLF。于是同一份内容：

| 换行 | 识别出的源码变量 |
|---|---|
| LF | `['mainSrc', 'code']` |
| CRLF | `['mainSrc']` ← 派生的那个凭空消失 |

后果是：存放在 CRLF 文件里的断言**不再被算作源码断言**，那道检查直接放行。也就是说，这条规则能不能起作用，取决于当初是谁、用什么编辑器保存的文件。

修完之后，仓库里真实的源码断言数从 **432 条涨到 716 条**——多出来的 284 条一直都在，只是以前看不见。

## 类型检查：抓到了 4 个真问题

项目没有类型系统，但加一份 `jsconfig.json` 开 `checkJs`，让 TypeScript 只做推导、只检查、不出产物。

首次接入报 95 条，逐条处理后归零。绝大多数是「注解没写全」的噪音，但有 4 条是真的：

| 位置 | 问题 |
|---|---|
| `lib/dir-move.js` | 判断搬家的函数读 `srcExists` / `srcIsDir` 两个字段，**JSDoc 里从没声明过** |
| `lib/disk-health.js` | 返回值注解写着 `totals`，代码里从来没有这个字段 |
| `lib/acl-repair.js` | 权限诊断有两条返回路径，字段不一致——「路径不存在」那条少了 `repairPossible`，界面会拿到 `undefined` 并显示「无法修复」 |
| `lib/mojibake.js` | 一个回调参数的类型注解写成了另一个函数的签名 |

这类问题的共同点是：**代码能跑，注释在骗人**。后来者照着注释调用，就会在某个分支上拿到 `undefined`。

## 拆分：`main.js` 从 5430 行降到 4437 行

文件系统相关的 28 个通道（读写、哈希、加密、分割、去重、压缩解压）搬到了 `ipc/fs-ops.js`（1062 行）。

搬运方式与之前两次一致：**整段照抄，只做两类机械替换**（`++jobSeq` → `ctx.nextJobSeq()`、`latestCancelable = X` → `setLatestCancelable(X)`），没有改动任何一行业务逻辑。

有 5 个函数（如 `writeFileAtomic`）在被搬走的这段里定义、但其他域也在用。处理方式是让模块**反向导出**、调用方改从模块取——而不是复制一份回去。复制会让两份实现慢慢分叉。

## 两份「产物校验」脚本重新生效

仓库里有两份脚本，作用是**把源码断言跑在打包产物里**，检查 `app.asar` 里真的是预期的那份代码。它们与源码层测试互补：源码全绿但打包漏了文件，只有这里能发现。

问题是：它们**从写完起就没被任何自动化流程调用过**。于是模块搬迁之后，里面的断言全部指向了已搬走的代码，6 条永久失败，没人知道。

现在两份都修好了（35/35、19/19），并接进了发布流程——每次发版都会跑。

## 其他

- **断言总数护栏**：新增一道检查，防止「某个测试文件里的用例被悄悄删掉一半，剩下的仍然全绿」。真删 3 条用例验证过，它会精确报出「基线 38 → 现在 35」。
- **合并重复的测试助手**：`rmDir` 原来在 7 个文件里各有一份，其中 5 份扛不住 Windows 偶发文件占用、2 份扛得住——表现为「同一台机器上有的测试偶发红」。统一到更强的那一份。
- `.editorconfig`：只规定今后的写法，不回头重写既有文件（那会让 `git blame` 大面积失真）。
