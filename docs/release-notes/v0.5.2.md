# v0.5.2 —— 面包屑每一级都能点回去 + 侧栏分隔线

两张截图两个问题，都是「看起来该能操作，实际不能」这一类。

## 面包屑：末级点了没反应

截图里是 `首页 / 安全与密码 / 剪贴板历史`。前两级本来就挂了 onclick，
但**用户看不出来**：鼠标移上去没有手型光标、没有 hover 变化、没有焦点环。
只有最左边的「首页」有 inline 的 `cursor:pointer`，其余层级连光标都不变。

更别扭的是末级。它渲染成蓝色（`.bc-current`，`var(--primary)`），
看着就是链接，点下去**毫无反应**——因为没挂 handler。

现在：

- 所有层级统一 hover 底色 + 手型光标 + 焦点环
- 末级点击 = **回到上一级**（`剪贴板历史` → `安全与密码`）
- 当前页用 primary 浅底 hover，与"往回跳的上一级"在视觉上区分开
- 整条面包屑可键盘操作（`role="link"` + `tabindex="0"` + Enter）

**为什么末级是"回上一级"而不是"重新打开当前页"**：
后者会让工具页整页重绘，用户刚输入的内容全丢。而用户在面包屑上的
典型诉求本来就是「往上走一层」——这也是文件管理器地址栏的默认预期。

## 一个被测试抓出来的边界

首页页面上，唯一的那个「首页」项**也被判成可点**了：它自带 `go`（回首页），
于是有手型光标、有 hover 底色，按下去什么都不会发生。

判据应当是「点击后视图会不会变」，而不是「有没有挂 handler」。已修正，
并有断言盯着（B2）。

## 侧栏分隔线

左侧导航和右侧内容区**底色完全相同**（都是 `--page-bg`），中间什么都没有。
长列表滚动时看不出导航到哪儿结束、内容从哪儿开始。

加了一条 `1px solid var(--border-light)` 的右边框。几个取舍：

- **用实线不用阴影**：阴影在深色主题下几乎看不见（深底上的暗影对比度极低），
  而这条线需要两种主题下都清晰。
- **用 `--border-light` 不用 `--border`**：前者是"分隔用的最淡一档"，
  比卡片描边再轻，不会喧宾夺主。
- **用 `border-right` 不用 `::after` 绝对定位**：线要跟着侧栏宽度一起走
  （收起时 224px → 64px），border 天然跟随盒宽，不需要额外同步宽度。
  `box-sizing: border-box` 已在全局声明，所以总宽仍是 224px 而不是 225px。

## 验证

**新增 `scripts/test-breadcrumb-nav.js`（14 条端到端）**。

「能不能点」不是源码里有没有 `onclick` 那么简单，要验的是：
点一下**视图真的变了**（有 handler 但写错，界面毫无反应）；
点末级是回上一级而不是重开当前页；首页那一项在首页上不可点。

分隔线那条尤其注意——**只判颜色是无效的**：把 `border-right` 改成 `none`
之后 `getComputedStyle` 仍然返回原来的 `borderRightColor`（颜色属性还在，
只是没有宽度、不画出来）。第一版断言就是这个写法，变异测试下照样绿。
现在要求「有宽度 **且** 颜色不透明」同时成立。

变异测试（都验过会红）：

| 变异 | 结果 |
|---|---|
| 末级不补"回上一级" | B6/B7/B11 红 |
| `border-right: none` | B12/B13 红（B14 仍绿，证实 border-box 布局没被撑开）|
