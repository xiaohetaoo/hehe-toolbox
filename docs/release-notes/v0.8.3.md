# v0.8.3 —— 六项体验扩展：拖到哪都能开、剪贴板一键动作、参数记忆、敏感信息自动清理、差异可合并、PDF 三件套

这一版回答一个统一的问题：**工具都在，但把它们串起来的路太长**。103 个工具各自能干一件事，用户却要「找到工具 → 打开 → 粘贴/选文件 → 再设一遍参数」。本版的六项改动都在缩短这条链路。

---

## 一、全局拖拽：文件拖到窗口任意位置，自动打开对应工具（新增）

**原来**：41 个工具文件里只有 1 个（file-unlock）支持拖拽，其余都要点开对话框翻目录。

**现在**：把文件拖到主窗口任何位置，会出现全屏虚线提示「松开以打开」，松手后按扩展名路由到能处理的工具：

- **唯一候选**直接打开（如 `.rar` → 7z 压缩包），不弹任何东西；
- **多个候选**一律弹选择面板，按扩展名分组列出，第一个预选中、支持方向键 + 回车、双击直达。

**为什么歧义不猜**（用户明确确认的策略）：猜错的代价是「打开了错误的工具 → 还得退回来重来」，比让用户点一下更贵。59 个扩展名 → 37 个工具的映射在 `lib/drop-route.js`，纯数据可单测。

**技术要点**：

- 工具页内已有的 dropzone **优先级更高**（用户已在图片压缩页里拖图，显然要压缩）——靠 `defaultPrevented` 区分；
- 交接用 `window.__pendingDrop` 队列：工具页不知道文件从哪来，只管「有就取」。队列取完即清空、30 秒过期，不串页；
- 所有走 `filePicker` 的工具自动接住拖拽文件（在 `ui.js` 里消费一次），40+ 个工具不用改一行代码。

## 二、剪贴板动作面板：Ctrl+Shift+V（新增）

复制了东西之后按 **Ctrl+Shift+V**：面板先识别内容类型，再给出对应动作。

| 复制的内容 | 给出的动作 |
|---|---|
| 图片 | 截图标注 / 贴图置顶 / OCR / 保存 / 压缩 |
| 文件路径 | 资源管理器 / 哈希 / 占用解锁 / 属性 |
| 网址 | 浏览器打开 / Ping / 下载 |
| JSON | 格式化 / 对比 / 统计 |
| Base64 图片 | 保存 / 标注 / OCR / 压缩 |
| 哈希值 | 说明 + 跳转哈希校验 |
| JWT | Base64 解码看载荷 |
| 颜色值 | 颜色转换（带色块预览） |
| 时间戳 | 时间戳转换（附换算结果） |
| 乱码 | 乱码修复 |
| 普通文本 | 统计 / 正则 / 对比 / 三栏 / 翻译 |

**两类错误都要防**：漏判（该认出 URL 却当文本）让用户看不到动作；**误判**（把短词当 Base64 图片）让用户点了得到一坨乱码。判定按特异性排序（路径 > 网址 > JSON > Base64 图片[必须解码后看文件头魔数] > 哈希 > JWT[必须能解出 header] > 颜色 > 时间戳 > 乱码 > 文本），27 项用例含 5 项反例全过。

**选点**：面板只走**窗口内**快捷键，不注册 `globalShortcut` —— 系统级注册会抢走浏览器里 Ctrl+Shift+V（粘贴为纯文本），那是越权。

**端到端实测**：剪贴板放 JSON → 面板点「JSON 格式化」→ 自动跳到工具页且内容已填入输入框。

## 三、工具参数记忆（已内建，本轮确认并接上拖拽）

审查中发现 `rememberToolParams` 已完整实现（结构键回填、600ms 合并写盘、切页补刷），**我此前另写的 `tool-state.js` 是重复造轮子**——已删除。本轮把 render 上下文补传了 `toolId`，为拖拽交接服务。

## 四、剪贴板历史：六档筛选 + 敏感内容自动清理（增强）

- **筛选从 3 档扩到 6 档**（全部/文本/图片/网址/JSON/哈希·令牌·颜色）。分类判据直接复用 `lib/clip-analyze.js`——面板与历史用的是同一套规则，不会出现「同一段内容在面板里叫网址、在历史里归文本」。
- **敏感内容自动清理**（默认关闭，用户主动开启）：形如 PEM 私钥、GitHub/AWS 令牌、JWT、身份证、银行卡、强密码的记录，10 分钟后自动删除。

**判据的根本取舍：宁可漏判，不可错判**——漏判只是多留一会儿，错判是删掉用户数据。所以银行卡规则要求**整段**就是 16 位（否则 20 位订单号中间会被切出 16 位误删）、超长文本一律不算凭据、置顶条目永不删、缺时间戳的条目按「刚复制」处理。15 项判定 + 7 项「绝不能误判」的反例全过。

## 五、三栏对比：从「只能看」到「能合并」（增强）

新增**合并模式**：每个差异行给 A / 基准 / B / 删除 四个单选，选完实时拼出结果，可复制、可另存。

**刻意不做三路自动合并**：git merge 那类自动合并边界情况极多，**合并错了比不合并更糟**（用户会以为结果可信）。这里是「人做决定、工具只负责拼装」，责任边界清楚。

默认策略：只有一方改的行自动采信（无争议），**冲突行默认停在基准并标红**——不替用户决定。边界处理：null 行跳过不塞空串、空字符串行保留（不是缺失）、缩进与行尾空白原样保留。

## 六、PDF 三件套（新增 3 个工具）

| 工具 | 能做 | 关键限制（界面上如实写明） |
|---|---|---|
| PDF 水印与页码 | 居中/平铺水印、5 种页码位置、跳过封面 | pdf-lib 标准字体只支持 Latin-1，**中文水印会直接拒绝并说明原因**（实测 pdf-lib 抛 `WinAnsi cannot encode "机"`），中文请用图片水印 |
| PDF 提取文字 | 按页提取、可选标注页号、复制/另存 | 只能提文字层；**扫描件会明确提示并一键跳转批量 OCR**，而不是给个空结果 |
| PDF 瘦身 | 删元数据、清冗余对象、对象流压缩 | 不能重编码页内图片流，对扫描件收益有限——省得少时如实说明原因 |

实测：3 页 PDF 加水印+页码后可读回、页数不变；瘦身 1656 → 1421 字节（↓14.2%）、元数据确实清空。

## 七、发布前深度审查：又修掉 6 个缺陷

六项功能写完后做了一轮长测审查（106 个工具页真机走查 + 18 组配色 + 全量代码复审），抓出并修掉 6 个问题。**其中两个是本次新功能自己带进来的，一个是安全方向的老漏洞**：

| 缺陷 | 后果 | 归因 |
|---|---|---|
| 电源门禁只认斜杠写法 | `shutdown -s /t 0`（横杠）**直接穿透门禁执行真关机**；反过来 `shutdown -a` 取消关机被误拦 | 老代码，安全方向 |
| 保活复用的工具页不消费拖拽 | 往「标签页已开着」的工具拖文件，文件**静默消失** | 本次新功能 |
| 剪贴板面板内容在同一路径蒸发 | 与上同源，内容躺 30 秒后消失 | 本次新功能 |
| 拖拽遮罩引用不存在的 `--bg-1` | 暗色主题下卡片背景透明、「消失」，且控制台零报错 | 本次新功能 |
| PDF「跳过前几页」页码语义与文案矛盾 | 界面说「封面不计页码」，实际跳 2 页后第 3 页仍显示「3」 | 本次新功能 |
| `DropOpen.bind` 缺幂等标记 | 切一次语言监听器翻倍，一次拖拽弹出 N 个选择面板 | 本次新功能 |

**一个反复出现的坑值得单独说**：新功能的全局监听挂在 `document` 上，而切换界面语言会整壳重建并再次调用 `bind()`。`clip-actions.js` 有幂等标记、`drop-open.js` 漏了 —— 这类「两处同构、只改一处」的缺口，本轮专门补了一条测试同时锁两边。

**长测里一个假警报也被纠正了**：压力测试一度显示 1272 次操作后堆停在 255MB（基线 5.7MB）。加充分沉降后复测 → 回落到 7.92MB，残留 +2.2MB / +2497 节点 / +858 监听器，恰好等于 6 个保活页的正常开销。是 GC 未沉降的测量误差，不是泄漏 —— 没有去「修」一个不存在的问题。

## 已知限制

- 拖拽路由按扩展名判定，无扩展名文件不路由（避免瞎猜）；
- 剪贴板动作面板的数字键快捷执行依赖面板焦点，键盘读屏器用户可直接 Tab 到按钮；
- PDF 提取文字对竖排/复杂排版可能顺序不佳（pdf.js 按内容流顺序返回）；
- **PDF 水印不支持中文**：pdf-lib 标准字体只覆盖 Latin-1，硬做会抛 `WinAnsi cannot encode "机"`。界面在提交前就拒绝并说明，不是静默出白图；
- **三栏对比不做自动合并**：合并错了比不合并更糟（用户会以为结果可信）。工具只负责拼装，决定权在人；
- 敏感内容清理基于形态判定，**不能替代密码管理器**——明文 JSON 里任何内容都应视为可读。
