# v0.6.0 —— 标签可以拖出来变成独立窗口

像浏览器一样：按住一个标签往标签栏外拖，松手就弹成一个独立窗口。

## 手势

按住标签**纵向**拖出 40px 以上，标签会变半透明 + 虚线框（告诉你"到位了"），
松手开窗。几处刻意的取舍：

- **只有纵向**才算。横向拖动是"调整顺序"的自然手势（将来可能做），
  而且标签栏本身横向可滚动，横拖应该是滚动。
- **阈值 40px**：太小的话点击时手抖两下就弹窗，太大则要甩鼠标。
- **必须 mouseup 才执行**：拖出去又拖回来 = 取消。与浏览器一致 ——
  用户会习惯性用"拖回原处"反悔。
- **不关闭原标签**。工具页可能正在跑任务（压制、扫描），关标签会触发页面清理、
  任务中断。多留一个标签的成本远低于"拖一下把正在跑的活儿弄丢了"。

没用 HTML5 drag & drop：它的 `dragstart` 会抢走 `click`，表现为"点标签不切换了"。
手写 `mousedown`/`mousemove` 能精确控制"点击"与"拖拽"的分界。

## 独立窗口长什么样

没有侧边栏、没有标签栏、没有搜索框，只有标题栏 + 那个工具。
它复用的是同一个 `index.html`（`?tool=xxx&standalone=1`），不是另做一个页面——
工具页依赖 20 多个 `<script>`，复制一份必然分叉（改了一条通道常量、独立窗还是旧的）。

同一个工具已经弹出去过时**聚焦那一个**，不再开第二个：
用户拖两次通常是不确定"上次成没成"，再开一个反而更乱。

## 这次真正的工作量：事件路由

这是改动里最容易出错、也最难归因的一处。

以前全进程只有一个窗口，所有 `send()` 都发它，从不出错。有了第二个窗口后，
同一个 IPC 通道会被两个窗口分别调用：主窗在压制视频、独立窗在扫描磁盘，
两边的 `job:stream` 都走同一个 `send()` —— **进度条互相串**。
而渲染层按 job id 前缀认领（`JobPrefix.subscribe`），认领不上的静默丢弃，
表现是"进度条不动"或"跳变"，完全看不出是两个窗口在打架。

修法不是改 50 处调用点，而是改 `send()` 的语义：

- `ipcMain.handle` 的包装层用 `AsyncLocalStorage` 把**发起调用的 webContents**
  记进上下文；
- 该 handler 派生的一切（`await`、`spawn` 的 data 回调、`setTimeout`）都携带它；
- `send()` 优先发给上下文里的那个窗口，没有上下文（定时任务、托盘、启动期）
  才退回主窗口。

**前提先验证过**：ALS 的上下文能穿过 `spawn` 的回调。这是整套设计的地基，
所以动手前写了个探针实测（`spawn` → `stdout.on('data')` → `als.getStore()` 仍然返回
发起者）。假设它不成立的话，整套路由得推倒重来。

`win:minimize` / `win:maximize` / `win:close` 同样要按发起窗口走。
否则点独立窗的最小化，最小化的是**主窗**——独立窗纹丝不动，看起来像按钮坏了。

## 一个只有真跑才会暴露的缺陷

独立窗口第一版是**完全空白**的。原因：

`render()` 里 `renderNav()` 排在 `renderContent()` 之前，而 `renderNav()`
第一行就是 `sidebarEl.querySelectorAll(...)` —— 独立窗没有侧栏，`sidebarEl` 是
`undefined`，于是抛 `TypeError`，`renderContent()` 永远不执行。

静态检查看不见、单元测试看不见、打开主窗看一眼也看不见（主窗永远有侧栏）。
只有真的用 `?standalone=1` 加载一次才会发现 body 里只剩脚本标签 + 一个空的 `.main`。

修法是给 `renderNav` / `renderBreadcrumb` / `renderTabs` 各加一道守卫。
测试 D7 专门盯着这一条（"工具页内容真的渲染出来了，不空白"），
变异测试验过：去掉守卫 → D7/D8 立刻红。

## 验证

**新增 `scripts/test-tab-detach.js`（17 条端到端）**，跑在真实 Electron 里：

拖出手势 8 条 —— 横向不触发、纵向触发、有视觉反馈、松手开窗、
原标签保留、拖回取消、阈值内不触发、从关闭按钮起手不触发、请求带对工具 id。
独立窗 8 条 —— 无侧栏/无标签栏/无搜索框、有窗口控制、面包屑无分隔符、
直接停在目标工具、**内容不空白**、有工具标题。

变异测试（都验过会红）：

| 变异 | 结果 |
|---|---|
| 去掉 `renderNav` 的 `if (!sidebarEl) return` | D7/D8 红（独立窗空白） |
| 阈值改 `dy > 5` 且去掉轴向判断 | T2（横向误触发）、T7（阈值内误触发）红 |

### 测试里两次假绿

**① 替换 `window.api.invoke` 数调用次数 —— 恒为 0。**
`app.js` 顶部是 `const { invoke } = window.api;`，解构出的局部变量，
之后再改 `window.api.invoke` 对模块内部完全无效。改成从主进程侧计数。

**② `invoke()` 已经把 `{ok, data}` 信封剥掉了。**
测试里写 `(await invoke('test:open-reqs')).data` —— 拿到的 `data` 是 `undefined`。
`invoke` 返回的就是 `data` 本身。

两次都不是被测代码的问题，是"测试自己写错了却看起来像功能坏了"。
