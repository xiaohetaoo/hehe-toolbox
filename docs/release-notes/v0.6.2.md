# v0.6.2 —— 标签拖出的真正原因：指针离开标签栏后就收不到事件了

上一版我判断错了。这次用真实鼠标事件（CDP）打日志，拿到了决定性证据。

## 实测日志

在标签上按下并往下拖，渲染层收到的真实事件序列：

```
bar-down  | t=tab-label | 313,66     ← 按下：到达标签栏 ✅
doc-move  | t=content   | 313,96     ← 移动：只在 document 上被看到
doc-move  | t=th-desc   | 313,146    ← 继续下移，target 已是内容区
doc-up    | t=th-desc   | 313,146
```

**一条 `bar-move` 都没有。**

原因很朴素：标签栏只有 36px 高。往下拖 40px 才能触发"拖出"阈值，而那时指针
早已离开标签栏，事件不再经过它。绑在标签栏上的 `pointermove` 自然一条都收不到，
拖拽状态永远停在 `out: false`，松手时判定为"没拖出"。

## 上一版为什么没修好

上一版我把 `pointerdown`、`pointermove`、`pointerup` 全绑在标签栏上（改成委托
之后）。委托解决了"标签重建导致监听丢失"，但没解决"指针离开容器"——后者才是
拖不出来的直接原因。

而所有测试都用 `dispatchEvent` 直接派发到 `document`/`bar`，**绕过了真实命中路径**，
所以测试全绿、真实操作无效。这正是这个缺陷能连续两个版本存活的原因。

## 修法

按面板分工：

- `pointerdown` → 标签栏（委托，要从具体标签反查工具）
- `pointermove` / `pointerup` / `pointercancel` → **document**（指针离开标签栏后仍能收到）
- 再加 `setPointerCapture`：把后续事件定向到被按下的标签，保证拖到窗口外松手也能收到 `pointerup`

后两条是**互为冗余**的双保险。变异测试验证过：单独去掉任一条，功能仍然正常；
两条都去掉才会失败。留着冗余是有意的——`setPointerCapture` 在合成事件下
可能抛异常（已 try/catch），而 document 监听在旧版 Chromium 上更稳。

## 验证

**给 `test-tab-detach.js` 加了两条真实鼠标用例（R1/R2）**，用 CDP 的
`Input.dispatchMouseEvent` 走完整命中/捕获链路：

- **R1**：往下拖 80px 后标签出现 `tab-drag-out`（证明 `pointermove` 越出标签栏仍被收到）
- **R2**：松手后主进程收到开窗请求

变异测试：

| 变异 | R1/R2 |
|---|---|
| `pointermove` 挪回标签栏 | 仍通过（`setPointerCapture` 兜住了） |
| 去掉 `setPointerCapture` | 仍通过（document 监听兜住了） |
| **两条都去掉** | **都红** ✅ |

这正是我想要的：断言锁的是**行为**（能拖出来），不是某一行实现。
两条路径任一条存在就能工作，两条都没了才算回归。
