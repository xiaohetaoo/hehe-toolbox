# v0.6.5 —— 标签拖拽改成浏览器语义：左右重排、四个方向都能拖出

上一版能让标签拖出成独立窗口，但**只支持向下拖**。往上拖完全没反应，往
左/右拖更糟：既不开窗，也不会换位置，什么都不会发生。

## 问题在哪

原来只有一条判据：

```js
const nowOut = dy > TAB_DRAG_THRESHOLD && dy > |dx|;
```

三个方向都被这一行排斥掉了：

- **向上** —— `dy` 是负数，`dy > 40` 恒假，怎么拖都不会触发
- **向左 / 向右** —— 横向位移根本不参与判据；而且**没有任何重排逻辑**，
  所以把标签往右挪一段，代码里连"该换位置"这个概念都不存在

而浏览器语义里，"栏内左右移动 = 调换位置"是最常用的一条。缺了它，
标签栏就只是"一排不能动的块"。

## 现在怎么判

```
① 栏内水平移动          →  重排（调换标签顺序）
② 指针离开标签栏矩形     →  拖出成独立窗口（上下左右一视同仁）
```

**为什么用"离开标签栏"而不是给每个方向定一个位移阈值**

阈值是猜出来的：40px 向下成立，向上要不要 40？向左呢？每个方向一个阈值，
等于维护四条互相打架的规则，而且它们在角落里会重叠（同时满足两条判据时
该算哪个？）。"有没有离开标签栏矩形"是几何事实，与方向无关，天然覆盖四个
方向，而且与用户的心智一致——浏览器的语义正是"拖出标签栏 = 拖出窗口"。

**纵向仍留 40px 阈值兜底**

标签栏只有 36px 高，往下拖 20px 就已经出界了。不设阈值的话，"手抖一下"
也会弹出窗口。所以纵向要求同时满足"出界"且"越过 40px"。

纵向还保留了一条"深度拖"判据（`ady > 40 && ady > adx*2`，指针仍在标签栏矩形内
也算出界）：从 v0.6.0 起用户就是这么拖的，老手势不能突然失灵。

## 两种结果的视觉刻意分开

| 手势 | 视觉 | 松手后 |
|---|---|---|
| 重排 | 半透明 + **蓝色落点竖线** | 标签换位置 |
| 拖出 | 半透明 + **虚线框** | 弹出独立窗口 |

用户第一次拖动时不知道这个手势会导向哪种结果，**视觉区分比文字提示有效**。
虚线框的语义是"松手会弹成窗口"，所以重排时绝不能带它——两个一起出现，
用户就懵了。测试里专门有一条断言锁这个（重排时断言 `.tab-reorder` 存在、
`.tab-drag-out` 不存在）。

**落点竖线为什么是一根线，而不是"把邻居推开"**

推开邻居需要给每个标签做 transform 动画。标签是 flex 子项，位置由布局决定，
要动画就得先算出每个标签的新 x 坐标再逐个写 transform，而这个序列在拖动
过程中每帧都在变——代价大、还容易抖。一条 2px 竖线插在"松手会落到的位置"
上，准确且不干扰布局：它是绝对定位的，压根不参与 flex。

## 重排的判据细节

- **横向阈值 6px**：指针按下去总会有 1~2px 抖动。没有阈值的话，"点一下标签"
  会被记成一次移动
- **落点按"过了标签中线"算**：用左边缘的话，指针停在某个标签的左半边时要
  等到完全越过它才算落点后移，观感上总慢半拍。中线是浏览器与文件管理器
  都用的手感
- **重排只调 `renderTabs()`，不调 `render()`**：后者会走 `renderPageCleanup`
  重建工具页，把正在跑的 ffmpeg 之类任务打断。用户只是把标签挪了个位置，
  任务不该因此中断一遍

## 过程中修掉的两个测试缺陷（都不是实现问题）

这两条值得记，因为它们差点造成假绿：

1. **沙箱里写死 `TAB_REORDER_THRESHOLD: 6`**
   —— 于是"把源码里的阈值改成 0"这个变异传不进沙箱，R6 一直全绿。
   它测的其实是测试文件自己的数字，不是实现。
   改成从 `js/app.js` 解析常量后，变异立刻被发现。
   同样的写法在 `test-tab-drag-cleanup.js` 里也有，一并修掉。

2. **e2e 里 `executeJavaScript` 的结果被 `JSON.parse` 了两次**
   —— 拿到的是字符串本身，`/tab-reorder/.test(对象)` 恒假。
   断言红而实现是对的，我一开始还误以为是实现 bug。

另外，写方向测试时想当然按"拖 120px"算终点，可标签栏从侧栏旁一直铺到
窗口右边（1000px 窗口下约 1000px），**向右拖 120px 根本还在栏内**。
改成先问标签栏要真实矩形，再按矩形算终点。

## 手感需要真机确认

自动化能证明"判据对、状态迁移对、真实鼠标事件能走通"，证明不了
"拖起来顺不顺手"。两个还在观察的点：

- **落点竖线是否够清楚**（不够的话可以改成"推开邻居"）
- **横向拖出标签栏是否过于敏感**（标签栏贴着左边缘，向左拖很短距离就出界）
  —— 如果确实太灵敏，加一个横向的最小位移阈值
