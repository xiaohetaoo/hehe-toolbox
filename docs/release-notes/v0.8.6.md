# v0.8.6 —— 4 个新工具 + 测试提速 20 倍

这一版有**四个新功能**，以及一项影响开发效率的基础设施改进。
另有 13 处缺陷修复，其中 7 处来自外部审查、我逐项实测复核后并入。

## 一、全局命令面板（Ctrl+K）

原来 Ctrl+K 只是「把光标放进搜索框」——首页聚焦大搜索框、其他页面聚焦标题栏那个。
问题是标题栏搜索只搜工具名、不显示所属模块，而且**只在固定位置**。

现在是一个不依赖当前页面的浮层：

- 唤起即聚焦输入框，输入即搜
- `↑↓` 选择、`回车` 打开、`Esc` 关闭、点遮罩关闭（点面板内不关）
- 底部常驻键位提示，不用猜怎么退出去
- 层级 2000，高于普通弹窗 —— 面板是「盖住一切」的全局 UI，不该被工具自己的弹窗压住

除了 106 个工具，还有五个全局动作：返回首页 / 打开设置 / 我的收藏 / 切换深浅主题 / 切换语言。
关键词里塞了同义词（「偏好」「preferences」「深色」「dark」），否则按英文或同义词找的人都搜不到。

**搜索排序一行都没重写**，全部走 `Registry.search`（含拼音首字母、英文名、精确/前缀加成）。
两份排序必然漂移，用户会发现「同一词在两处搜出来的顺序不一样」，所以只保留一份。

降级：若面板模块因加载顺序或异常没就绪，Ctrl+K 退回原来的聚焦搜索框 —— 快捷键不能变成「按了没反应」。

## 二、工具链（批处理编排）

把压缩 / 打包 / 解压 / 哈希 / 批量重命名 / 转 PDF 串成一条流水线，一键跑完并给出**逐文件报告**。

设计上有个关键取舍：**原子单位是「可无头执行的操作」而不是「带 UI 的工具页」**。
把工具页串起来在技术上能做（调用 render 再模拟点击），但那等于把界面当 API 用 ——
界面上任何改版都会悄悄打断所有工具链，中间态（进度、弹窗）也没法统一处理。

失败策略是双层的：

- **单文件失败只标记那一个，其余继续** —— 50 张图坏 1 张不该丢 49 张好的；
- **但第一步对全部文件都失败时立刻抛出** —— 那通常是参数错或环境缺失，继续跑只会产生 N 条一样的错误。

## 三、PDF 页面管理

已有的 PDF 工具做整体合并拆分、水印页码，但最常见的需求其实是**页级操作**：
第 3 页是空白要删掉、扫描件顺序乱了要重排、横向扫描的几页要转 90°。
这些用「拆分再合并」也能做到，但那是把一个动作拆成三个工具用。

- 页码范围支持 `1,3,5-8`（也容错全角逗号、倒写区间 `8-5`）
- 上下调序、单页旋转 90°、单页移除、按范围删除/保留
- 改动只存列表状态，点「另存为」才写盘 —— 可以先连做几步再保存

两个实现上的坑（代码里写明了原因）：

- **旋转必须累加在已有角度上**。扫描件本身常带 `/Rotate 90`，直接 `setRotation(90)` 等于把它归零，用户点旋转却看不到变化。
- **每次 build 都从源文件重新 load**。`removePage` 会重排内部索引，在同一对象上连续操作很容易拿错页。

界面里明说了两条限制：旋转只改显示角度、不重编码内容流（老阅读器可能忽略）；
加密 PDF 会被忽略加密状态后另存（原文件受密码保护时，结果可能打不开）。

## 四、窗口布局预设

`winmgr` 原来只能置顶、调透明度、置底 —— 都是针对单个窗口的。
「把这三个窗口摆成左右分屏」得手动拖，而拖到像素级对齐很费劲。

六种布局：左右分屏 / 上下分屏 / 四宫格 / 三分（左大右两小）/ 主窗左其余右列 / 层叠。
**选择器用示意图而不是文字按钮** —— 布局是空间关系，一张缩略图一眼就懂；
「三分（左大右两小）」这种描述光靠文字要在脑子里建模。

示意图**直接用几何计算的真实输出画**，不另画一套静态图 —— 否则改了算法就会出现
「图上这么摆、实际那么摆」的分叉。测试里逐个比对 SVG 每个矩形的坐标与计算结果。

Win32 侧三个要点：先 `ShowWindow(SW_RESTORE)`（最大化窗口直接 SetWindowPos 不会按预期移动）、
`SWP_NOZORDER | SWP_NOACTIVATE`（一次摆四个时若每个都激活，焦点会落在最后一个）、
参数在 IPC 边界强制取整并夹取（传 NaN 会让窗口跑到屏幕外且不报错）。

## 五、测试提速 20 倍（开发效率）

**问题**：190 个测试全量跑一次 310 秒，改一行代码也要等 5 分钟。

**改完**：改 `pdf-plus.js` 只跑 1 个测试（<1 秒），改媒体模块跑 16 个（约 12 秒），
只有改 `main.js` 这类全局文件才全量。

```bash
npm test -- --changed          # 按 git 改动算出该跑哪些
npm test -- --feature pdf      # 只跑某个功能域
npm test -- --list-features    # 列出所有功能域
```

**为什么不是给每个测试打标签**（最初是这么想的）：

- 190 个测试里 50 个不读任何项目源码（纯 e2e 直接起 Electron），归属无法从源码推断；
- 其余 140 个里 56 个读 3 个以上源文件，本身跨多个域；
- 手工给 190 个文件加注释，改功能时忘了同步标签 → **漏测是静默的**，比没有标签更危险。

所以改成维护一张 25 行的「功能域 → 源文件/测试」表，改了什么文件就反查涉及哪些域。
表小、改功能时一眼能看出该更新哪一行。

保守优先：命中 core 域（main/channels/scripts）→ 全量；改动文件不属于任何已登记域 → 全量并提示；
只改测试脚本 → 只跑它自己。

## 六、首页分类加介绍

原来分类卡片只有一行关键词（「哈希校验、批量重命名、加密分割」），
用户看完知道「有哪些东西」、不知道「这一包能解决什么」。说明只挂在 `title` 属性里，
不悬停就完全看不到。

给 10 个分类各写了中英两段介绍（两三句，说清「能干什么」而不是罗列名词），
卡片上显示首句、模块页顶部显示完整版。

排版调了三轮（前两版被判「太丑、拥挤」）：最终 3 列、`padding 18/20`、行高 1.8、
`grid-auto-rows: 1fr` 强制等高、`max-width: 42ch` 限制行宽、三档断点。
实测 10 张卡片全部 335×131，宽高完全一致。

## 七、缺陷修复（13 处）

**安全/数据完整性**

- **电源门禁嵌套绕过**：`if 1==1 if 2==2 shutdown /s` 等 9 种写法穿透
- **录制拼接遇单引号路径必失败**：用户名带 `'` 时暂停的录制降级成只保住第一段
- **GitHub fine-grained token 漏判**：`github_pat_` 前缀整条放过，一直留在明文剪贴板历史

**功能缺陷（7 处来自外部审查，逐项实测复核）**

- 命令面板副标题丢模块名（传字符串 id 给需要对象的 `modName`）
- 工具链哈希结果全为空（`r.sha256` → 实际是 `r.hex.sha256`）
- 工具链 bmp 输出「内容是 PNG、名字是 BMP」
- 工具链图片转 PDF 静默丢图（逐文件转换只取第一个结果，却报「N 张已合成」）
- 取色后「复制为」面板不刷新（主取色路径漏调，两条路径不一致）
- PDF 删空回滚用 1..N 重建，抹掉未写盘的重排
- 窗口布局按钮高亮不动（重绘进新建的 box，页面挂的却是旧的）

**其他**

- 首页分类网格无响应式断点（800px 以下溢出视口）
- 文档预览转换产物无人清理（`preview-tmp` 无限堆积）
- 拖拽区 busy 状态无视觉反馈
- `refresh` 图标弧线与箭头不在同一圆上，看着像乱线
- 下载续传用例的时序竞态（`write` 后定时 `destroy`，负载高时客户端只读到 3 字节）
- `run-tests` 与断言守卫的总数口径不一致（差 1 条）

## 已知限制（未变）

- **电源门禁是语法层防护，不是安全沙箱**：能静态识别的形态都拦，`iex` 这类「字符串即代码」只能整条 fail-closed
- PDF 水印不支持中文（pdf-lib 标准字体只有 Latin-1）
- PDF 旋转只改显示角度，少数老旧阅读器可能忽略该标记
- 三栏对比不做自动合并（合并错了比不合并更糟）
- 敏感内容清理基于形态判定，不能替代密码管理器
- 窗口布局只在主显示器工作区内排列，跨屏行为未定义
