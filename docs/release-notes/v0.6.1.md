# v0.6.1 —— 三个反馈的修复：面包屑点不动、标签拖不出、标签溢出

## ① 面包屑点了没反应 —— 被窗口拖拽区吞掉了

上一版给面包屑加了 onclick、hover 反馈、键盘可达，**没有一个能生效**。

根因：`.titlebar` 整条是窗口拖拽区（`-webkit-app-region: drag`），而这个属性
会被**子元素继承**。面包屑没有自己的 `no-drag` 声明，于是鼠标按下时被系统当成
"拖窗口"，点击事件根本到不了 span。

搜索框和右侧窗口按钮早就各自声明了 `no-drag`，唯独面包屑漏了。

这类遗漏极具迷惑性：代码看起来完全正确，鼠标移上去 hover 也生效（CSS 工作正常），
但点击毫无反应——**事件在更早的一层就被系统拿走了**。

## ② 标签拖不出来 —— 逐标签绑事件不可靠

上一版给每个标签各绑 `mousedown`，再由 document 上的 `mousemove`/`mouseup` 收口。
两个隐患：

- `renderTabs` 每次重建标签，那些监听跟着重建——只要有一次在重建期间发生
  （打开工具的瞬间），拖拽就丢了；
- 合成事件测试用 `dispatchEvent` 直接派发到 document，**绕过了命中测试**，
  于是测试绿、真实操作却是坏的。

改成事件委托：监听挂在标签栏（生命周期与壳一致），用 `e.target.closest('.tab')`
找标签。同时换成 `pointerdown`/`pointermove`/`pointerup`——指针事件统一处理
鼠标/触控/笔，还能拿 `pointerId` 去重。加了 `pointercancel` 收口，避免系统抢走
指针后状态卡住。

## ③ 标签超出窗口不压缩

原来只有 `overflow-x: auto`，而标签是 `white-space: nowrap`：标签一多，后面的
被挤出右边界，而本项目的滚动条是**全局隐藏**的（`* { scrollbar-width: none }`）——
于是完全没有任何线索表明右边还有标签。

改成弹性压缩：`flex: 0 1 auto` + `min-width: 0` + `max-width: 200px`，文字省略号。

### 中间踩的一个坑：固定像素下限是错的

第一版给标签写了 `min-width: 56px`（"至少放得下图标 + 两三个字"）。实测在
125% 缩放的窗口里：标签栏可用 327px，8 个标签 × 56 = 448px，**照样溢出 5 个**。
压缩生效了，但被下限顶住。

固定像素下限在自适应布局里总是错的：容器宽度不确定，任何绝对下限都会在某个
宽度下溢出。改成完全弹性后：`scrollWidth === clientWidth === 327`，8 个标签
各约 35px，全部可见。

窄到只余图标时靠两件事保证"认得出"：
- 图标 `flex: none`，永不被压缩（16px 始终完整）
- 每个标签有 `aria-label`（`makeButtonLike` 设的），悬停可读全名

padding 也用 `clamp(4px, 1.2vw, 12px)` 跟随收缩——默认 12px×2 = 24px 的留白
在 35px 宽的标签里占掉七成。

## 验证

**新增 `scripts/test-tabbar-breadcrumb-fix.js`（14 条端到端）**：

- ① 面包屑：`webkitAppRegion === 'no-drag'`、标题栏本身仍是 `drag`（窗口还能拖）、
  点中间级/末级都能跳转
- ② 拖拽委托已挂上、标签带 `data-tool-id`
- ③ 开 10 个标签后**没有标签被挤出可视区**、总宽不超过标签栏、
  图标未被压缩、每个标签都有可读名称

变异测试（都验过会红）：

| 变异 | 结果 |
|---|---|
| 去掉面包屑的 `no-drag` | F2 红（`appRegion=none`） |
| 恢复 `min-width: 120px` | F10/F11 红（溢出 8 个，总宽 1200 vs 可用 295） |

**一个诚实的边界**：F2 抓的是 CSS 声明，不是"点击真的穿透了"。因为
`element.click()` 是合成事件，不走系统的命中测试——去掉 `no-drag` 后 F4
（点面包屑跳转）**仍然通过**。这正是这个缺陷能活过一个版本的原因：
所有测试都用合成点击，而合成点击绕过 `-webkit-app-region`。

真实的鼠标事件测试（`sendInputEvent`）在本机跑不通：DPR 3.75 下
坐标换算不可靠，事件投递不到渲染层。这一点没解决，已记录。
