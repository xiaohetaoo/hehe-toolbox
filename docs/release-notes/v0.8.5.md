# v0.8.5 —— 第三轮深度审查：9 个缺陷修复

这一版**没有新功能**。v0.8.4 之后做了一轮真机深度审查（106 个工具全量走查 + 视觉专项 + 安全链路 + 20 分钟长稳），修掉 9 个缺陷。

其中两个是**安全方向**的实质漏洞，建议所有用户升级。

---

## 一、电源门禁可被嵌套结构与变体绕过（安全 · 高）

v0.8.4 修掉了 `if` / `{}` / `iex` 的**单层**形态，但本轮实测发现**嵌套与变体**仍全部穿透。下面这些写法 `isPowerCommand` 返回 `false`，而在 cmd / PowerShell 里**真的会关机**：

```
if 1==1 if 2==2 shutdown /s
for %i in (x) do if 1==1 shutdown /s
(if 1==1 shutdown /s)
powershell -c "switch (1) { 1 { Stop-Computer } }"
if /i "a"=="a" shutdown /s
powershell -c "iex ('Stop-'+'Computer')"
powershell -c "iex (Get-Content c:\x.txt)"
```

**根因**：平铺判定只剥一层壳。`iex` 的判据还要求「段内可见危险词根」，而字符串可以拼接、也可以从文件读。

**修法**：把「一段文本有无危险可执行位」收成**递归函数** `textHasDanger(text, depth)` —— `for` 体 / `if` 体 / `(…)` 组 / `{…}` 组都作为新文本递归判定，嵌套多少层走同一套判据（深度 >8 fail-closed）。`iex` / `Invoke-Expression` 改为**出现即拦**（与 `-EncodedCommand` 同取舍：内容不可静态判定就不放行）。`stripIfCondition` 重写为引号感知，覆盖 `/i` 开关与带空格引号比较。

**回归**：16 条必须拦全部拦下（含嵌套），17 条必须放行全部放行（日常命令 / 纯取消关机 / 仅提到 shutdown 的文本）。

## 二、录制分段拼接遇单引号路径必失败（数据完整性 · 高）

分段目录在 `%TEMP%` 下含用户名。用户名带单引号（如 `O'Brien`）时，concat 清单 `file 'C:/Users/O'Brien/…'` 在引号处提前闭合 → ffmpeg 失败 → 暂停过的录制**降级成只保住第一段**。

**修法**：新增纯函数 `lib/fs-ops.js concatFileLine(p)`，用**闭合引号式** `'…'\''…'` 转义。

**这个转义形态是真跑 ffmpeg 验出来的**：造 `O'Brien` 命名目录、生成 3 段各 1 秒视频，四种候选各跑一次:

| 转义方式 | 结果 |
|---|---|
| 闭合引号式 | 成功（3728 字节） |
| 不转义 | Error opening input files |
| 引号内反斜杠 | Error opening input files |
| 双引号包裹 | Invalid argument |

再用 ffprobe 确认成品时长 **3.00 秒** —— 三段都拼进去了，不是只保住第一段。

## 三、剪贴板敏感清理漏掉 GitHub fine-grained token（安全 · 中）

敏感判定只认 `ghp_` / `gho_` / `ghu_` / `ghs_` / `ghr_` 经典前缀，而 GitHub 2022 年后的 fine-grained token 前缀是 `github_pat_` —— 这种形态**整条放过**，会一直留在明文剪贴板历史里。用户开了「敏感内容自动清理」时，其它凭据 10 分钟后都清了，唯独这种留着。

**修法**：新增独立判据，长度下限 30（前缀之后）防误伤 —— `github_pat_short` 这类短串不命中，普通文本不受影响。

## 四、首页分类网格无响应式断点（视觉 · 中）

`.home-cats` 固定 `repeat(4, 1fr)`，全项目此前**没有任何宽度断点**。真机视口走查（CDP Emulation 5 档宽度 × 4 个视图）发现在 800×600 与 640×500 下 `.home-cat` 右缘超出视口（6 / 20 处），分类名与计数被截在窗外。

**修法**：`max-width: 1023px` 降两列。复测 20 个组合全部无溢出。

## 五、文档预览转换产物无人清理（磁盘 · 中）

`doc-preview` 每预览一个 Office 文档，就在 `userData/preview-tmp` 留一份 LibreOffice 转出的 PDF（渲染层把 outDir 指到那里，预览完没人删）。PPT / 大 Word 转出的 PDF 可能几十 MB，长期使用一直堆积 —— 而启动清扫家族（`sweepTempFiles` / `sweepClipImages`）都没覆盖这个目录。

**修法**：新增 `sweepPreviewTmp()`，并入启动清扫。按 mtime 保留 24 小时内的文件 —— 刚转换出来正在预览的那份不会被误删。

## 六、拖拽区 busy 状态无视觉反馈（视觉 · 低）

目标体积压缩等工具运行时给拖拽区加 `busy` 类（注释明说"busy 样式"），但 CSS 无对应规则 —— 功能上已被 `picker.setLocked` 锁定，视觉上却毫无表示。

**修法**：补 `.dropzone.busy { opacity: .55; cursor: not-allowed }`，全部用主题变量。

## 七、两个测试基础设施缺陷

**下载续传用例的时序竞态**：测试服务器 `res.write('AAAA')` 后 `setTimeout(50ms) destroy` —— `write` 只进 Node 发送缓冲，全量跑 185 个脚本时机器负载高，客户端可能只读到 3 字节连接就被 RST 掐断（RST 丢弃接收缓冲里未取走的数据）。断点保存为 3，第二个请求发 `Range: bytes=3-`，与断言 `bytes=4-` 不符，用例假失败。

根治方案：`res.end('AAAA')` —— 声明 `Content-Length: 8` 却只发 4 字节，`end` 触发正常 FIN，客户端**必然**先收满 4 字节再收到截断。「已收到 = 已发送」恒成立，零时序依赖。2 个忙循环进程施压下连跑 6 次全过。

**`run-tests` 与断言守卫的总数口径不一致**：同一仓库两处报出 2118 与 2119，差值来自 `test-target-e2e.js` —— 它不打印 PASS 行、靠退出码记 1 条，守卫有表、`run-tests` 不知道。两个数字对不上时没人能判断是"有人删了测试"还是"只是口径不同"。已统一并加守卫比对两张表。

## 三个假警报（纠正后没去"修"不存在的问题）

1. **剪贴板读写全为空** —— 本机 360 安全卫士锁住剪贴板，PowerShell `Set-Clipboard` 同样失败。环境限制，非应用缺陷（剪贴板链路在正常桌面环境多轮验证过）。
2. **CDP 报 nodes=30 万** —— 那是整个渲染进程的计数（含 GC 待回收），真实 DOM 只有 1162 节点，沉降后 heap 回落到 12MB。
3. **9 处"spawn 无 error 监听"** —— 注释行误匹配 + 追踪窗口太窄，精确扫描确认全部有监听。

## 已知限制（未变）

- **电源门禁是语法层防护，不是安全沙箱**：能静态识别的形态都拦，`iex` 这类「字符串即代码」只能整条 fail-closed。真正的边界仍是「用户是否开启了这个能力」；
- PDF 水印不支持中文（pdf-lib 标准字体只有 Latin-1）；
- 三栏对比不做自动合并（合并错了比不合并更糟）；
- 敏感内容清理基于形态判定，不能替代密码管理器。
