# v0.9.0 —— 开发环境修复与加固

第五轮审查后的一轮集中修复：开发环境（v0.8.9 新增）涉及**用户 PATH** 的 5 处缺陷全部修掉，另有 4 项健壮性加固；工具页文案补齐英文。

## 一、修复（按危险程度）

1. **中文 PATH 读回乱码**：`readUserEnv` 缺 UTF-8 强制，中文系统按 GBK 输出、按 utf8 解码 → 含中文的 PATH 读回即乱码，随后写回会**损坏用户 PATH**。现强制 UTF-8，并改用 `DoNotExpandEnvironmentNames` 读未展开原值。
2. **跨卷安装搬运失败**：`moveFile` 的 EXDEV 回退用 `copyFile`，对目录必失败（EPERM）。现按 `isDirectory()` 分流，目录走递归复制 + 目标校验。
3. **PATH 类型被降级**：`.NET SetEnvironmentVariable` 恒写 REG_SZ，含 `%VAR%` 的 REG_EXPAND_SZ 会被写成字面量。现按 `GetValueKind` 用注册表提供程序原类型写回。
4. **缓存包哈希不符死循环**：完整但校验失败的缓存包会反复重下同一错包。现先校验缓存、不符删包重下，再次不符报「期望/实际前 8 位」明确错误。
5. **并发写丢更新**：apply/unapply/manifest 无锁，两个操作交错会互相覆盖。现串行锁 + 同一运行时安装互斥 + 界面操作期间禁用按钮。

## 二、加固

- 启动清扫超龄 `.staging-*` / `.old-*` / `.env-write-*` / `.term-*`；新增「清理安装包」（通道 195 → **196**）。
- 探测改为四组并行 + 60 秒缓存；跳过 `WindowsApps` 的 python 别名（避免误弹商店）。
- 「打开带环境的终端」改临时 `.cmd`（chcp 65001 + ASCII 提示），不再拼 `cmd /k` 命令行。
- 删除环境失败时保留 manifest 便于重试；取消下载/解压后的残留有兜底清理。

## 三、界面

- 开发环境正文接入工具页双语（`env` 域、`i18n: true`），英文界面不再整片中文。
- 冲突警告与「本机已装」使用运行时名称（Python / Node.js…）而非内部 id。

## 四、验证

- 全量 **205 脚本 / 2288 条断言 / 0 失败 / 3 环境跳过**；lint 0、typecheck 0。
- 真机 E2E：安装 Node → 加入用户环境（PATH 类型保持 String）→ `node -v` → 撤销后 PATH 逐字还原 → 删除干净。
- 真实注册表只读对照：读回值与独立读取逐字一致，无乱码。
- 已知边界不变：便携 Python 不被 `py` 启动器 / PEP 514 识别；MSVC 只给官方入口；版本固定、无自动更新。
