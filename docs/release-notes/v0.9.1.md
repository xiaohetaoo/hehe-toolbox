# v0.9.1 —— 第六至十一轮审查修复

本版是连续六轮深度审查（第六～十一轮，含对抗性实测）的集中落地：修复 4 个真实缺陷，并补齐两处「记录未修」的收尾项。

## 一、安全修复

1. **电源门禁间接执行绕过（P0）**：`& (Get-Command Stop-Computer)`、`& (gcm Stop-Computer)`、`powershell -c "& (Get-Command …)"` 这类写法在 PowerShell 里会真的执行关机，但门禁只认危险词根、不认「取命令再调用」的间接形态，直接放行。现增加「`get-command`/`gcm` + 调用运算符 + 危险词」三要素判据；纯查询（无调用运算符）仍放行，实测无误伤。
2. **删除还原点的模式兜底 fail-open（P1）**：`mode === 'oldest' ? '/oldest' : '/all'` —— 任何非 `oldest` 的值（拼错、undefined、未来新增入口传错）都会删光该卷全部卷影副本且不可恢复。现改为白名单：只认 `oldest`/`all`，其余拒绝。
3. **批量重命名的暂存名脱离临时名白名单（P1）**：两阶段执行把文件改名为 `.hehe-ren-<ts>-<seq><ext>`，而清理白名单不认识这种形态——中途崩溃/断电后文件留在隐藏临时名下，用户看到文件「消失」且清扫扫不到。现已登记白名单，并新增**崩溃恢复**：执行前把「暂存名→原名」清单写入 store，工具页渲染时检测残留并支持一键恢复。

## 二、健壮性修复

4. **ZIP 解压失败回滚残留空目录（P2）**：回滚原来只删已写文件，`dirFor` 新建的目录留在用户目标里（CRC 错时多出一串空目录）。现新增 `ensureDirectoryInsideTracked` 记录本次新建目录（EEXIST 的不算），失败时由深到浅 `rmdir`；非空目录保留（可能含并发写入，误删更危险）。

## 三、界面与文案

- `.btn-danger:hover` 不再硬编码颜色，改为跟随主题（9 套配色 × 明暗正交下 hover 始终是本主题危险的变亮版）。
- 设置页高危分区新增说明：「开发环境加入/移除用户 PATH 不走本页门禁」，写明原因（改前备份、可撤销、仅当前账户、默认加入是产品行为），避免后来者误当漏洞加回门禁。
- 批量重命名页新增崩溃残留的恢复提示。
