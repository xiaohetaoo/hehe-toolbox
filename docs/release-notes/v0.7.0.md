# v0.7.0 —— 重发 v0.6.9 的内容，并把发版流水线修好

这一版**没有新的应用改动**。它就是 v0.6.9 那 24 项修复，重新发一次。

## 一、为什么要重发

v0.6.9 的 tag 推上去了，但**没有产出任何可下载的文件**。

失败链（已用 GitHub API 逐步核实）：

| 步骤 | 结果 |
|---|---|
| 4 Install dependencies | success |
| **5 Ensure electron binary is downloaded** | **failure（仅 11 秒）** |
| 6–14 后续 9 步 | **全部 skipped —— 代码一行都没被执行到** |
| 15 Normalize release title | failure（`if: always()` 兜底步骤） |
| 16 Ensure release notes | failure（同上） |

第 5 步做的事只有一件：跑 `node_modules/electron/install.js` 把 200MB 的
electron 二进制下下来。它失败说明 CI runner 上 `objects.githubusercontent.com`
不可用 —— 与代码无关。

同一份代码的 CI（不是 Release）当时是**通过的**，只是两个 workflow 跑在不同
runner 上、网络状况不同。

## 二、顺手修掉的三处流水线问题

### 1. electron 下载没有重试

`ci.yml` 与 `release.yml` 各写了一段一模一样的内联 bash，都没有重试。
v0.6.8 的 CI 是 120 秒超时，v0.6.9 的 Release 是 11 秒失败 —— 同一个原因。

现在收口到 `scripts/ensure-electron.js`：

- 4 次重试，退避 5/10/20 秒
- **每次重试前清掉半成品** —— `install.js` 看到残缺的 `dist/` 会认为
  "已下载"直接跳过，于是重试 N 次其实什么都没做
- 失败时输出 `::error::` 并写明重试次数，让人一眼看出该重跑还是查网络

### 2. 兜底的红灯把真正的失败盖住了

v0.6.9 日志里最后两条红是「标题未统一」和「找不到 release」，
而真正的失败是「Release 根本不存在」。看日志的人会去查标题逻辑，方向完全错。

根因是那两步都挂了 `if: always()`，Release 不存在时照样执行、照样失败。

现在按职责拆开：

| 脚本 | 职责 | Release 不存在时 |
|---|---|---|
| `fix-release-title.js` | 改标题 | 跳过（exit 0） |
| `ensure-release-notes.js` | 补正文 | 跳过（return） |
| `verify-release.js` | **判发布成败** | **`::error::` + exit 1** |

顺手修了个真 bug：`fix-release-title.js` 的 `resolveTag()` 直接取
`process.argv[2]`，加上 `--if-exists` 后会把开关当成 tag，报"格式可疑"——
而真正的问题恰恰是"不该报错"。

### 3. 没有最终校验，空发布只能靠人眼看

新增 `scripts/verify-release.js`，用 GitHub 的最终状态反查，不信中间步骤的
退出码：

- tag 对应的 Release 存在？
- 不是 draft（draft 用户看不见）？
- 挂了 Portable `.exe` 与 `.zip`，且都不是 0 字节？

**只认后缀，不认 `assets.length`** —— GitHub 会给每个 Release 自动附
Source code (zip)/(tar.gz)，只看数量会把"只有源码"误判成成功。

## 三、应用代码：与 v0.6.9 完全相同

24 项修复原样保留，包括：

- **6 处会静默丢数据的问题**：CSV 表头重名丢列、JSON→CSV 对非对象数组
  产出垃圾、批量重命名预览与实际不符、拖拽文件夹静默截断、剪贴板上限
  按字符而非字节、PDF 导出图片空白
- **4 处界面显示错误**：时间戳工具「本地时间」显示 UTC、相对时间出现负号、
  英文界面按模块搜不到、Unicode 控制字符转义失效
- **2 处崩溃风险**：番茄钟裸 `Notification` 打断状态机、弹窗无法用 Esc 关闭
- **2 处性能问题**：日历翻月 31 次串行 IPC、展开传参求极值的守卫有盲区
  （修好守卫后立刻抓出 3 处真实写法）
- **2 处多窗口不一致**：独立窗口设置不生效（`Prefs.set` 整对象覆盖会互相回滚）、
  睡眠/锁屏定时切页即失效
- **4 处安全加固**：权限默认全开、`window.open` 未拦、PDF 导出 HTML 未净化、
  CSP `connect-src` 过宽
- **4 处可维护性**：`preload` 的 `isDev` 失败开放、文件名用 UTC、
  过时路径注释、两张 job 前缀表描述漂移

完整清单见 `docs/release-notes/v0.6.9.md`（那一版的应用改动说明）。

## 四、为什么版本号是 0.7.0 而不是 0.6.10

本仓库的版本规则不允许某一段出现两位数：

```
✗ 版本号不合规：0.6.10
  规则：每一段只能是 0–9，满 10 向前进位。
  应写为：0.7.0
```

这条规则由 `scripts/version.js` 强制，`npm run version:check` 也会在 CI 里跑。
所以按进位写成 **0.7.0**。
