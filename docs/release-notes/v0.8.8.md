# 核核工具箱 v0.8.8

本版包含两部分：一轮系统化的代码审查修复（18 处），以及四项新功能。

## 一、深度审查修复（18 处，8 P1 + 10 P2）

**P1（功能失效 / 安全边界）**

1. **便携版自动更新从未真正生效**：更新脚本以 UTF-8 无 BOM 写盘，而 Windows PowerShell 5.1 对无 BOM 的 .ps1 按系统 ANSI 代码页解码；脚本内嵌的路径又恒含中文（`%APPDATA%\核核工具箱`），于是路径变成乱码 → `Get-Item` 失败 → 脚本 exit 1，主进程却已退出。用户看到「正在重启升级」，重启回来还是旧版。`rollback.ps1` 同病，兜底也坏。现统一走 `lib/ps-script.js` 加 BOM，并用真跑 PowerShell 5.1 的测试钉住。
2. **电源门禁新增三类绕过**（`for /f %i` 间接取程序名、`!VAR!` 延迟展开、cmd 的 `^` 转义）：未开启「系统电源操作」也能执行关机。现补 fail-closed 判据与误伤回归。
3. **拖文件到已保活的工具页会静默丢失**：复用路径拿 `window.__renderingTool` 比对，而该值停在上一个渲染过的工具上，队列被判「不属于我」后 30 秒过期；反向错位时还会把文件塞进别的工具。现显式传 `v.toolId`。
4. **PDF 只勾「页码」必崩**：水印文字清空后字体未 embed，页码分支取 `font.widthOfTextAtSize` 直接 TypeError —— 而「只要页码」正是该工具最自然的用法。改为无条件 embed。
5. **工具链「计算哈希」把结果全丢了**：哈希算出来只用于一句计数，报告里没有任何值。现按文件回填并逐条渲染。
6. **窗口布局首屏空白**：`render()` 从不调用 `loadWindows()`，「窗口」卡片一片空白；切语言后 `chosen` 残留，会排列界面上看不见的窗口。现首屏自动枚举并裁剪失效选择。
7. **录制中途进程死亡仍报「录制完成」**：停止时直接 return、丢弃退出码，半截 mp4（moov 未写出）按体积报成功。现记录异常退出并降级提示、保留分段。
8. **更新包下载一次没装就再也下不了**：目标已存在被拒，而界面此时已无下载/安装按钮。现只对本应用自己的更新包允许清旧重下，用户路径仍然拒绝。

**P2（边界 / 加固）**：命令面板 Tab 后 Esc/↑↓ 失效；取色器每次取色累积整屏 canvas 闭包（1080p ≈ 8MB/次）；PDF 页面管理读取失败后状态半更新；拖拽区双击并发弹两个对话框；`update:apply` 接受渲染层指定的替换目标；powershell 起不来仍静默退出；7z 提交 rename 覆盖竞态；原子写把目录改名成备份还报成功；盘符相对写法 `D:` 被判成 cwd；`\\?\` 前缀绕过关键目录闸门。

## 二、四项新功能

- **空间分析器**：分区容量（statfs）+ 大文件 TOP + **逐层下钻**（面包屑 / 上一级 / 目录体积递归累计），纯只读。
- **垃圾清理扩类别**：新增下载目录安装包（默认不勾选）、Windows 更新缓存、`Windows\Temp`、`Windows\Logs`、WER；需管理员的类别会标出，失败如实进 errors。
- **启动项扩面**：注册表 Run 之外，新增启动文件夹 / 计划任务 / 自启服务的只读汇总，并提供打开系统对应界面的入口；该工具改为「部分锁定」，未开注册表能力时也能查看。
- **系统还原点**（新工具）：列表 / 创建 / 启用系统保护 / 删除。删除走新增的第 11 项高危能力「删除系统还原点」，并明确告知会连带清掉该卷上的其它卷影副本。

## 三、测试与工程

- 修掉一处**测试假绿**：三条真跑 ffmpeg 的测试此前把用户目录硬编码成空的 `%APPDATA%\hehe-toolbox`，导致「本机没有 ffmpeg」整段 SKIP；现按 `package.json` 的 productName 定位（+17 条断言恢复执行）。
- `load-fs-ops-handlers` 补 `nextJobSeq`，扫描类通道首次可被行为测试真正调用。
- 测试规模：**199 个脚本 / 2243 条 PASS / 0 失败 / 2 个环境跳过**；lint 0；typecheck 0；断言基线 2243。
- 规模：**110 个工具 / 10 模块**；IPC 通道 **188/188**（新增 7 条）；高危能力 **11** 项。
- 真机验证：打包态冒烟 `pages=110`；CDP 驱动验证空间分析器「扫描 → 下钻 → 面包屑」全链路；三个新/改页面截图比对；启动项查询 PS 耗时从 4.7s/19KB 优化到 2.4s/1.3KB（并行 + 服务端过滤）。

## 四、已知限制（诚实说明）

- 审查报告里 8 项**低置信**结论本轮未修（zip 目录放大未计数、`junkScanCache` 无过期、crash-log `<tmp>` 脱敏为死代码、download 清理覆盖原错误、pdf.js 不 destroy、dragDepth 判定不对称、录制 24h 分段清理、`tempPathFor` 未纳入一致性测试）—— 它们还缺可复现证据。
- 安装包扫描只覆盖 `%USERPROFILE%\Downloads`；用户改过下载位置会显示「没有可清理项」。
- 计划任务 / 自启服务只展示不代改：改动需要系统工具或管理员权限，代改风险过高。
- 删除还原点依赖 `vssadmin`，需要管理员；存储占用解析不出时显示「取不到」而不是假数字。
