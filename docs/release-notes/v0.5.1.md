# v0.5.1 —— 「前往设置」跳到位，而不是把用户扔在设置页顶部

一个具体的小问题：剪贴板历史页提示「本工具的『删除文件』属于高危操作，
需在设置中开启」，下面是「前往设置 → 高危功能」按钮。点下去之后，
用户看到的是**设置页的「通用」分区**。

他得先找到「高危功能」那一栏，再在十几个开关（删除文件 / 清理垃圾 /
取得所有权 / 编辑 hosts / 写注册表…）里逐个读标签，去找名字和提示语
对得上的那一行。提示语已经告诉他答案了，界面却不认。

## 改了什么

点按钮之后：

1. 直接切到「高危功能」分区（不是停在「通用」）
2. 滚到**这个工具缺的那一项**，并闪一下高亮（1.6 秒后自动消失）
3. 把焦点放到那个开关上 —— 键盘用户落地就能按空格

带过去的是能力 id（`file-delete` 这种），不是显示名：
显示名会随语言变，id 不会。

高亮用 `outline` 而不是 `border`：border 会改变盒模型尺寸，整行会跳一下。
动画只做颜色、不做位移 —— 位移类提示在长列表里容易让人以为「内容变了」。
`prefers-reduced-motion` 下改成静态底色，仍能看出是哪一行。

## 顺手补的一个键盘死角

开关（`switchEl`）是个 `div` + click 监听，这也是**设置页所有行为开关**
（开机自启、关闭到托盘、高危功能那一整屏）的实现：

- Tab 走不到它 —— div 不进 tab 序列，键盘用户够不着任何开关
- 读屏软件读不出「这是个开关、现在开着还是关着」

补上 `role="switch"` + `tabindex="0"` + `aria-checked`，空格键切换。
用 `role=switch` 而不是 `role=button`：读屏会念「开关，已开启」，比「按钮」准确。
空格必须 `preventDefault` —— 否则按一下开关、整个设置页往下滚一屏。
Enter **不**作为切换键：那是 button 的约定，混用会让用户按回车意外打开高危功能。

`aria-checked` 跟着状态同步更新（`set()` 里也更新），否则读屏播报会永远停在初始值。

## 验证

**新增 `scripts/test-danger-jump.js`（10 条端到端）**。要验的三件事只有跑起来才知道：

1. 点按钮后分区真的切到了 danger（不是默认的 general）
2. 目标那一行真的被滚进了可视区（`scrollIntoView` 对游离节点无效，
   而且 danger 分区是异步画的 —— 时机错了就滚不动）
3. 高亮类真的出现，且**过一会儿自动消失**（常驻高亮会让人以为这一项被选中了）

夹具把 `file-delete` 放在 5 个能力的**中间**：如果实现是「滚到第一行」
或「滚到最后一个」，`C4/C5/C6` 会失败，而不是碰巧通过。

变异测试（都验证过会红）：
- 退回到「只切分区、不带能力 id」→ C5 高亮、C6 滚动、C7 焦点全红
- `openSettings` 里丢掉 `capId` → 同上

- `npm test`：**1498 通过 / 0 失败**（117 个脚本），新增 10 条
- `lint` 0、`typecheck` 0

版本 0.5.0 → 0.5.1。
