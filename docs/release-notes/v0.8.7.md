## 一、电源门禁可被 wmic 绕过（安全 · 高）

对抗性抽查 EXEC.RUN 门禁时发现：`wmic os where primary=1 call shutdown`
不含任何已知词根（shutdown / stop-computer / setsuspendstate /
lockworkstation / powrprof），`POWER_CMD_RE` 与 `textHasDanger` 都放行——
**系统直接关机**，且不需要开启「系统电源操作」。

这条命令网上搜「定时关机命令」很容易找到，绕过门槛与直接输入 shutdown
相同的结果却不需要开启门禁——防护不一致。

**修复**：DANGER_TOKENS 加 `wmic`（整词根，宁可多问：wmic 正在被微软弃用，
普通用户极少用，误拦也只是多确认一次）。

**测试**：test-powergate-ps.js 30 号用例——3 条 wmic 绕过形态必须拦、
4 条无害命令（ipconfig/notepad/echo/dir）确认不误伤。

## 二、expr-eval 百分号歧义（功能 · 高）

`50%*2`、`50%/2`、`sqrt(4)%`、`(2+3)%` 这些常用写法**直接抛错**。
根因有两层：

- `isPercentAt` 把 % 后面的 `*`/`/`/`^` 一律当二元取余——但取余的右操作数
  不可能以二元运算符开头，parser 只能报「表达式无效」。
- 左侧操作数改写只 `out.pop()` 一个 token——括号式/函数式会被毁掉括号结构
  （`sqrt(4)%` 报「括号不匹配」）。

Windows calc 与 Google 对 `50%*2` 都按 `0.5*2=1` 求值。

**修复**：① `%` 后面是 `*`/`/`/`^` 时判为百分比后缀；② 左侧操作数改写
弹出完整的操作数（括号式弹到配对 `(`，函数名一起包进 `(X/100)`——
漏掉函数名会得到 `sqrt(4/100)=0.2`，语义全错）。

**测试**：test-expr-eval.js 28/29 号用例共 19 项（含嵌套函数链
`sqrt(sqrt(4))%`、`%` 与乘除幂/括号/取余的全矩阵）。

## 三、Markdown 预览防御深度缺失（安全 · 中，4 处）

office.js / dev.js / text-tools.js 的 marked.parse 全是
「有 DOMPurify 就 sanitize，没有就原样 innerHTML」的降级写法——
DOMPurify 缺失意味着环境异常，此时打开含脚本的 .md 文件就是 XSS。

**修复**：无 sanitizer 时退化为纯文本预览（textContent），不再渲染 HTML。
text-tools 的另一处原本就用 escapeHtml+pre（已安全），不动。

**测试**：test-markdown-sanitize.js 4 条——守卫+退化+依赖声明逐处锁定。

## 四、objectURL 泄漏（资源 · 中，3 处）

media/shared.js 的 `loadImg`、qr.js 的 `handleFile`、screenshot-ocr.js 的
`fromBlob` 每次创建 blob URL 却从不 revoke——高频工具（压缩/水印）
一次拖几十张图就是几十个悬空 blob（截图 blob 单个几 MB）。

**修复**：统一模式「存当前 URL，进函数先释放上一次的，清空预览也释放」；
shared.js 的 loadImg 在 onload/onerror 里 revoke（解码后数据已在 img 里，
URL 再活着只是让 Blob 无法回收）。

## 五、错误消息注入面（安全 · 中，3 处）

qr.js L37、sys-tools.js L693/L750 把 `e.message` 拼进 innerHTML 未转义——
qr 的错误来自 qrcode 库（数据过长时可能回显用户输入），
sys-tools 的来自 Windows 服务 API（服务描述来自第三方软件）。
拼进 innerHTML 就是一条「错误消息即注入点」的路径。

**修复**：三处包 `escapeHtml`（qr.js/sys-tools.js 的解构同步补上）。

## 六、批量工具缺停止能力（可用性 · 中，3 处）

img-compress / img-watermark / batch-ocr 的批量循环没有取消能力——
压缩 200 张大图只能干等或杀进程。这三个工具走渲染层 canvas 循环
（没有可杀的子进程），不能像 ffmpeg 任务那样用 JOB.KILL。

**修复**：统一模式 `cancelFlag` 标志 + 循环每轮开头检查 break +
「停止」按钮 + 收尾复位（标志与按钮都要复位，否则第二次直接 break）。

**测试**：test-batch-cancel.js 4 条——声明/循环检查/停止按钮/收尾复位。
真机验证：三个工具页都渲染出开始+停止按钮。

## 七、URL 解码失败静默清空（可用性 · 低）

text-codec.js 的 URL 半边解码失败（裸 %、非法 UTF-8 序列）时
catch 里只写 `out.value = ''`——输出框直接消失，用户以为工具没反应。
同一文件的 base64 半边对同类问题有三类中文归因（decodeErrHint），
两套标准是明显的不一致。

**修复**：catch 分支复用 decodeErrHint 给出中文原因。

## 八、UI 一致性（4 处 + 守卫）

- **缺失图标 ×2**：snip-2 标注工具栏引用 `palette`/`line` 但图标库里没有——
  iconSvg 对未知名**静默回退成 info**，两个按钮显示一样的图标。已补进图标库。
- **空态文案统一**：「暂无记录」「没有记录」语义相同分属不同工具，
  统一为「没有」（4 处：net-tools/security/sys-tools）。
- **escapeHtml 显式解构 ×12**：错误路径上的安全敏感依赖显式化，
  不再依赖 `Object.assign(window)` 的隐式全局。

**新增守卫**：test-ui-consistency.js 5 条——图标引用全覆盖（含带引号键）、
必需图标防误删、style 不写死 #hex、window.ui 双导出面覆盖、解构不回退。

## 九、其他

- **refresh 图标画歪**：弧线跨 3/4 圈、箭头落在另一段弧上，拼起来是
  「线条互相穿插」的乱线观感。换成标准的「圆弧 + 单箭头」。
- **测试基础设施**：test-packaged-assets 原来找「任意版本的 zip」，
  改了源码但没重新打包时会报「新增 js 文件缺失」（看起来像代码 bug、
  实际是产物过期）。现在只认与 package.json 同版本的产物，不符则 SKIP。
- **js/channels.js 陈旧注释修正**：迁移状态注释还写着 v0.4.0 的事实。

## 已知限制（未变）

- **电源门禁是语法层防护，不是安全沙箱**：能静态识别的形态都拦，
  `iex` 这类「字符串即代码」只能整条 fail-closed；wmic 的**查询类**命令
  （`wmic os get caption`）也会被拦——宁可多问一次的取舍。
- PDF 水印不支持中文（pdf-lib 标准字体只有 Latin-1）
- PDF 旋转只改显示角度，少数老旧阅读器可能忽略该标记
- 三栏对比不做自动合并；行数不一致时逐行对齐会标「行数不一致」
- 敏感内容清理基于形态判定，不能替代密码管理器
- 窗口布局只在主显示器工作区内排列
