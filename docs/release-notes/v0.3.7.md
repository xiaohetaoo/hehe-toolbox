# 核核工具箱 v0.3.7

本轮为**工程质量改造**，目标是降低后续维护成本。**不改任何用户可见行为**：重构只搬代码、不动语义。

测试断言 **1091 → 1195**（全绿），新增 ESLint 且 0 error / 0 warning。

## 主要重构

### 拆掉两个巨无霸

- **`js/tools/media.js`（1822 行 / 16 个工具）→ `js/tools/media/*.js` 17 个文件**。最大单文件从 1822 行降到 236 行。
- **`main.js` 7722 → 6214 行（−1508）**。搬出 `ipc/ctx.js`（显式依赖注入）与 `ipc/dir-acl-links.js`（1653 行）。

任务书原本要求把两个域拆成两个文件，但实测它们互相依赖 19 个函数（`dirMoveRun` → `collectLinks`/`linkNatures`、ACL → `readAclFacts`、`verifyCopy` → `hashFile`），强行拆开只会新增跨模块导出，因此按真实依赖合并为一个。

### 测试骨架与断言质量

- 34 份重复的 `t()` 收进 `scripts/lib/harness.js` 一份。
- 测试分道：`npm run test:unit`（约 12 秒）与 `npm run test:ui`，整体耗时从 222 秒降到约 122 秒。
- **源码断言改行为断言**（样板：file-tools 失败明细）。原来那两条断言锁死的恰是缺陷本身。

### 其它

- **接入 ESLint**（唯一新增依赖，devDependencies）。当轮就抓出两个真 bug：`js/app.js` 里 finally 引用 try 块内的 `let dlId`（每次必抛 ReferenceError）、`js/tools/life.js` 的 `countIn` 创建后从未被读取（目标番茄数输入框无效）。

- **job id 认领收成 `JobPrefix.subscribe`**（6 处手写前缀匹配）。
- **IPC 通道名常量化**：先迁 2 个域（8/164 个通道），审计从「扫源码」升级成「比对表」。
- **i18n 建立机制 + 迁两个样板工具**（二维码、哈希校验）。中文模式直接返回字面量、不查表，因此中文下零行为改动是结构上保证的；英文模式漏翻回退中文，不会出现空白或键名。其余 98 个工具保持中文，边界已写进设置页文案与 README。

## 修好的缺陷：乱码修复在短文本上失效

报告 MJ-2 指出常用字样本太窄。复现后确认，并发现**两个报告未提及、更严重的问题**：

1. **常用字样本只有 101 字**。`娴嬭瘯`（`测试` 的 GBK 乱码，最高频的真实形态）与正确文本都命中 0/2 → 同分 40，strict-keep 拒绝修复。`Hello 涓栫晫` 甚至比 `Hello 世界` 得分更高。现在换成 GB2312 一级字库 3755 字（用 `TextDecoder` 现算，与标准定义机器可校验地一致；精简 ICU 运行时退回保底样本）。**修复率 11/22 → 17/22**。

2. **`best` 永远是原文**。`ordered = [keep, ...better, ...others]` 把原样无条件放在第 0 位，而 `best = ordered[0]` —— 注释写的「严格优于才顶上去」这条规则从未生效过。文本路径对任何乱码都返回原文。

3. **`analyzeWithEncoder` 绕过全部护栏**。它才是应用真正调用的路径，却直接 `concat + sort`。实测**正常文本被改坏 5/19**（`Hello 世界` → 两个 Unicode 私用区字符，渲染出来像空白，看着像「中文整句消失」）。现在两条路径共用同一个排序函数。

修的过程中又实测抓出三道判据漏洞并补了断言：Unicode 私用区字符、整段变问号（正常韩文被改成 `? ? ?? ??? ???`）、信息量骤减；另去掉 `latin1→UTF-16` 这支噪音源。
