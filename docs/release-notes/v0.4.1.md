# 核核工具箱 v0.4.1

这一版装了两样东西：**让故障可查的崩溃日志**，和**一整批日常使用中的小改进**。工具从 100 个增加到 102 个。

测试断言 **1273 → 1448**，工具数 **100 → 102**，`main.js` **4437 → 4343 行**。

## 最重要的一件事：出问题之后终于有迹可循

打包后的 exe **没有控制台**。而在此之前，主进程的异常处理只有一行：

```js
process.on('uncaughtException', (err) => console.error('uncaught', err));
```

`console.error` 写进一个不存在的终端。用户遇到「点了没反应」「窗口自己没了」时，现场一个字节都没留下——既没有文件，也没有界面入口。

现在三类事件都会落盘到 `%APPDATA%\hehe-toolbox\logs\`：

| 事件 | 触发场景 |
|---|---|
| `uncaughtException` | 主进程未捕获异常 |
| `unhandledRejection` | async handler 里被吞掉的 Promise 失败 |
| `render-process-gone` | 渲染进程 OOM / 被杀 / asar 被动过 |

设置 → 数据 里有入口：显示已记录几条、上次是否异常退出、「查看」按需读取、「打开目录」方便打包发给开发者。

日志会做脱敏（路径里的用户名 → `<user>`），单文件上限 256KB、留 5 份。

**顺带修掉一个会误报的缺陷**：自动更新重启走的是 `app.exit(0)`，而它**跳过 `will-quit`**——清理会话标记的那一步永远不执行。不修的话，每次自动更新后下次启动都会误报「上次异常退出」。

## 键盘用户之前完全用不了这个软件

导航项、工具卡、首页分类、标签页、笔记列表、日历格子——全是 `div` 加点击事件。Tab 走不到、回车没反应、读屏软件读不出这是按钮。

**100 个工具页对纯键盘用户是完全不可达的。**

现在补上了 `role="button"` + `tabindex` + 回车/空格处理，与鼠标走同一条代码路径。焦点环用 `:focus-visible`（鼠标点击不留环）。

## 拖拽文件夹：之前是个会报错的坑

把「下载」文件夹拖到图片压缩上，它把**目录本身**当成一个文件——`fs:stat` 拿到 `isDir: true`，然后按文件去读，报错「压缩失败」。

用户看到的是「软件坏了」，而不是「不支持文件夹」。

现在拖入即递归展开（深度上限 8、文件数上限 3000）。展开期间拖拽区显示「正在展开文件夹…」，否则扫几千个文件时用户以为没生效会再拖一次。

## 搜索支持拼音

打 `ys` 能找到「压缩」，打 `hxxy` 找到「哈希校验」。

实现是**零依赖**的：发现 `Intl.Collator('zh-CN')` 的排序就是拼音顺序，于是用「锚点区间判定」代替拼音数据表。

多音字按 collation 的默认读音：`重 → z`、`长 → z`、`行 → x`。所以「重命名」是 `zmm` 而不是 `cmm`——这与输入法习惯一致。

## 两个新工具

**图片混淆**（第 101 个）——用密钥把像素按可逆置换打乱。用途是「不想让人随手看到」：截图里带工号、给孩子看的答案图。

界面上用醒目颜色写明了：**视觉混淆不是加密**。它只打乱像素位置，直方图等统计特征仍在，有心的攻击者能恢复大致轮廓。真需要保密请用「文件加密解密」——那条说明就写在工具里。

**三栏对比**（第 102 个）——以基准版本为中心，并排看 A / B 两处改动。七种判定各有颜色，其中两处是刻意区分的：

- 「两边改成一样」标绿，不是冲突——否则用户白核对一遍
- 「两边都删了」与「只有一边少」分开——后者可能是没粘全

## 工程质量

**测试命令从 3955 字符降到 62 字符。** 原来 `test:unit` 是一行近 4000 字符的 `&&` 链，加一个测试要改那一行，漏登记就等于没跑——已经发生过两次。现在 `scripts/run-tests.js` 自动发现、自动分组。

**找回 20 条从未运行过的断言**：`test-harness.js` 一直躺在磁盘上，但从没进过任何命令。

**`main.js` 从 4437 行降到 4343 行**：network 域（7 个通道）搬到 `ipc/net-lan.js`。

## 两个主动放弃的目标

有两项工作我评估后**没有做**，理由写进了 `docs/decisions/`——不是"来不及"，而是做了会让质量变差：

**源码断言全量改写**（420 条）。两次尝试筛选"该改写的"都失败：按脆弱度筛出 27 条大多是误判，按静默失效筛出 30+ 处也大多是误判。根本原因是"源码断言"不是同质类别——「index.html 引入了某个文件」这类**没有行为可以验证**，验证「uncaughtException 会落盘」需要制造真实未捕获异常，那会杀死测试进程本身。

**合并 UI 测试的 Electron 启动**。实测能省 38 秒，但会让 21 个独立测试捆成一个进程——某个探针把进程搞崩（截屏/ffmpeg 类真的会），后面全部不执行，且报告只说"第 N 个探针失败"。
