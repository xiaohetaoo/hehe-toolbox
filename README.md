# 核核工具箱 (HeHe Toolbox)

> Windows 桌面效率工具箱 · 110 个工具 · 全部本地运行

![tech](https://img.shields.io/badge/Electron-43-165DFF)

## 快速开始

```bash
npm install        # 首次安装依赖（已配置 npmmirror 镜像）
npx electron .     # 启动应用
```

> 若首次安装后提示 "Electron failed to install correctly"，执行：
> `ELECTRON_MIRROR=https://npmmirror.com/mirrors/electron/ node node_modules/electron/install.js`

## 架构

```
main.js            主进程：窗口/托盘/全局热键 + IPC 能力层
                   （文件系统、哈希/加密、进程、网络、系统信息、静态服务器…）
preload.js         contextBridge 安全暴露 API
js/
  api.js           IPC 封装（浏览器演示模式自动降级）
  ui.js            组件库（表格/弹窗/Toast/开关/拖拽区/折线图…）
  registry.js      工具注册表（插件化：新增工具一行注册，自动进导航+搜索）
  app.js           外壳：路由/标签页/收藏/最近使用/设置页
  tools/*.js       按模块分组的工具实现
  tools/media/     多媒体工具（任务 9 从 media.js 拆成 18 个文件，shared.js 必须最先加载）
ipc/
  ctx.js           主进程闭包状态的显式上下文（窗口/任务表/任务序号/推送）
  dir-acl-links.js     目录搬家 + 权限/链接两个 IPC 域（任务 5 从 main.js 搬出）
  media-ffmpeg.js      FFmpeg 环境与音视频转码 + 屏幕录制两个 IPC 域（任务 6 搬出）
```

- 配置与数据保存在 `%APPDATA%\核核工具箱\hehe-data.json`（收藏、最近使用、剪贴板历史、便签、快捷项、命令收藏），全部本地存储。
  ⚠️ 目录名是 **`核核工具箱`**（= `package.json` 的 `productName`，Electron 默认按它取 userData），
  不是 `hehe-toolbox`：后者只有 `bin\`（FFmpeg），别按它找数据。
- 所有联网功能（公网 IP、翻译、测速）仅在用户主动点击时发起。
- **踩过的平台坑都记在 [`docs/decisions/`](docs/decisions/)**：一议题一文件，
  每条包含「现象 / 实测方法 / 结论 / 影响到的代码位置」。
  源码里对应的注释末尾会写一行 `详见 docs/decisions/xxx.md`。
  改那附近的代码之前先看一眼——那些结论都是实测出来的，不是推测。
  目前收录：Restart Manager 拒收目录（整批 ERR 5）、RM 拿不到文件↔进程映射、
  junction 不需要符号链接特权、PowerShell 换行即语句分隔符、
  icacls 的 `/Date(...)/` 序列化、Windows rename 会覆盖、
  剥注释必须识别正则、剥注释必须保留行号、全局 TextDecoder 污染、
  零用例注册必须判失败、用例必须写在 `done()` 之前、
  断言数守卫（删掉一半测试也要判红）、源码断言不做批量改写、
  UI 测试不合并成一个大 Electron、乱码修复遇 U+FFFD 不再二次编码。

## 开发与质量

```bash
npm test           # 全部测试（197 个脚本 / 2204 条断言，约 6 分钟）
npm run test:unit  # 纯 node 的测试（不启 Electron、不 spawn 外部进程，164 个脚本，约 1.5 分钟）
npm run test:ui    # 启 Electron / 调外部命令的测试（33 个脚本，约 4.5 分钟）
npm run lint       # ESLint 静态检查（退出码 0 = 通过）
npm run typecheck  # tsc -p jsconfig.json（checkJs，不出产物，退出码 0 = 通过）
```

- **分道的判断标准**：脚本若 `require(electron)`、启动 electron 二进制、或 spawn
  外部进程（powershell / cmd / mklink 等），归 `test:ui`；其余纯 node 的归 `test:unit`。
  日常改代码跑 `npm run test:unit`（约 1.5 分钟）；只改某个功能域时用
  `node scripts/run-tests.js --feature <id>`（0.3–15 秒，26 个域，`--list-features` 列全部）；
  提交前跑 `npm test`。

- **测试骨架**：所有测试脚本共用 `scripts/lib/harness.js`（`t(name, fn)` + `done()`），
  不要再在单个脚本里自己写一份 `t()`。异步用例直接传 `async` 函数，harness 会等待。
- **测试断言怎么写**：能用行为断言（跑真实现、断言返回值）就不要写源码断言。
  源码断言对字面敏感 —— 历史上 3 次 CI 中断都是「实现对了、字面变了」。
  确实必须写源码断言时，按 `scripts/lib/harness.js` 顶部注释的三点要求写清理由。

- **读源码用哪个入口**（拆文件之后这一点最容易踩）：

  | 你要验的是… | 用 |
  |---|---|
  | 某个文件里确实有这段实现 | `readSrc('路径')` |
  | 「一个逻辑单元拆成了多个文件」的整体 | `readTree('目录')`（媒体工具 → `readTree('js/tools/media')`） |
  | 「主进程里有这个 handler / 函数」 | `readMain()`（main.js + ipc/ 自动拼接） |

  **`readTree` / `readMain` 会破坏「A 出现在 B 之前」这类跨文件顺序断言** ——
  那种情况必须按明确文件读，或者改成行为断言。`scripts/test-round13-fixes.js`
  就因为从 `main.js` 改成 `readMain()` 一次性红了 11 条（`extract()` 的花括号配平
  跨过了文件边界），最后退回只读 main.js。改这类断言前先确认它依赖不依赖单文件连续性。
- **ESLint 存量问题**：`scripts/lint-baseline.md` 登记了本轮不修的既有问题（行级压制，
  不是文件级 disable）。lint 现在是 0 错误 0 警告；**它哪天变红，说明新增了问题**。
  规则集刻意只开能抓真实 bug 形态的那几条（`no-undef` / `no-unused-vars` /
  `no-shadow` / `no-dupe-keys` / `no-unreachable` / `no-async-promise-executor` /
  `eqeqeq` / `no-misleading-character-class`），没开代码风格类规则。
- 想重新生成压制清单：`node scripts/gen-lint-baseline.js`（它会先还原到压制前状态再重新压制）。
  该脚本依赖 `*.lintbak` 备份；**备份不在时它会中止且不写文件** ——
  否则会把基线文档静默重写成「0 处」（源码已是压制态，ESLint 报不出问题，而 `npm run lint` 照样返回 0）。

## 界面语言的边界（第 4 项改造）

现状是**部分双语**，并且这个边界写在了设置页与这里，不让用户期待落空：

| 范围 | 中文 | English |
|---|---|---|
| 导航 / 首页 / 模块名与描述 / 设置页 / 状态栏 / 对话框与 toast | ✅ | ✅ |
| 已迁正文的 11 个工具（二维码生成/识别、哈希校验、三栏对比、截图标注、EXIF 查看、Base64/URL/Unicode/HTML 实体/Hex 转换） | ✅ | ✅ |
| 其余 98 个工具页的正文 | ✅ | ❌ 仍是中文 |

机制在 `js/tools/i18n.js`：调用点写 `TT('qr', '保存 PNG')`，**以中文原文作键**。
这个方向是刻意反过来的 ——

- 中文模式**直接返回调用点字面量、不查表**，所以「中文下零行为改动」是结构上保证的，
  不依赖表里的中文写得对不对（表里也就不存中文，少一半维护量）；
- 英文模式查表，**漏翻回退中文**。漏一条的表现是「这一条还是中文」，
  而不是空白 / `undefined` / 键名。
- 对比 `T('qr.save')` 键名方案：键名要求每个调用点再想一个名字，
  且中文原文与键名一旦漂移就会出现「文案改了、键没改」的静默错误。
  用中文原文做键，改文案时漏改表会立刻退回中文（**可见**），不会静默错。

新增一个工具的双语：在 `js/tools/i18n.js` 的 `TOOL_TEXT` 里加一个域，
调用点写 `TT('域', '中文原文')`。`scripts/test-tool-i18n.js` 会自动校验
「调用点用到的每一条原文都有英文」与「表里没有孤儿条目」，
`scripts/test-tool-i18n-e2e.js` 则在真实窗口里验证切到英文后已迁移的工具页真的变英文。

## 打包发布

```bash
npm run dist:retry       # 便携版单 exe + 免安装 zip → dist/（推荐）
npm run dist:installer   # NSIS 安装版 → dist/hehe-toolbox-Setup-<版本>.exe
```

- **两种发布形态**：
  - `hehe-toolbox-Portable-<版本>.exe` —— 单文件，双击即用；每次启动要先把 Electron 解压到临时目录，冷启动 6~16 秒。
  - `hehe-toolbox-<版本>-win-x64.zip` —— 免安装目录版，解压一次后每次启动约 1.1 秒，在意启动速度就用它。
- 配置与数据保存在 `%APPDATA%\核核工具箱`，与开发版共享，便携版/安装版/开发版数据互通
- **不要用 `npm run dist` 直接构建**：它会往 `dist/` 写中间产物 `win-unpacked`，而本机文件观察器会长期锁住其中的 `app.asar`（EBUSY）。`dist:retry` 会把中间产物放到工作区外的暂存目录，只把最终产物拷回来。
- 重新构建需设置镜像：`ELECTRON_MIRROR=https://npmmirror.com/mirrors/electron/ ELECTRON_BUILDER_BINARIES_MIRROR=https://npmmirror.com/mirrors/electron-builder-binaries/ npm run dist:retry`

## 高危功能开关

有 11 项破坏性能力**默认关闭**，需到「设置 → 高危功能」里逐项开启（开启时会二次确认）：

| 能力 | 影响 |
|---|---|
| 删除文件 | 删除重复文件、空目录、笔记、剪贴板图片等（不进回收站） |
| 垃圾清理 | 清理临时文件、浏览器缓存、缩略图、下载目录安装包与系统日志（安装包默认不勾选） |
| 清空回收站 | 永久清空，不可恢复 |
| 结束进程 | 强制结束任意进程，未保存数据会丢失 |
| 停止系统服务 | 依赖该服务的程序可能异常退出 |
| 关机 / 重启 / 休眠 | 系统电源操作（锁屏与睡眠不受限制） |
| 编辑 Hosts | 写入系统 hosts 并刷新 DNS，影响全机解析 |
| 注册表与右键菜单 | 删除开机自启项、切换 Win11 经典右键菜单 |
| 目录搬家（建链接替身） | 把目录搬到别处并在原位置建目录联接；失败时可能留下坏链接 |
| 取得所有权 / 修复权限 | 改文件所有者并授予完全控制；会放宽该路径（及其子项）的访问权限 |
| 删除系统还原点 | 删除卷影副本（还原点）；不可恢复，且会同时清掉该卷上的其它卷影副本 |

这些工具在界面上用**红色卡片**标出，与普通功能区分。主进程侧有硬门禁 —— 即使渲染层被绕过，未开启的能力也无法执行。

## 自动更新与 CI

- **检查更新**：设置页「关于」一键检查。安装版走 electron-updater（NSIS 全量升级）；便携版查询 GitHub Releases 最新版，检测到新版本后内置下载（进度显示），下载完成可点「🚀 重启并替换」自动覆盖程序文件并拉起新版（配置与数据不受影响）；也可手动打开所在目录自行替换。查询带 **ETag 条件请求 + 6 小时本地缓存**，正常使用几乎不消耗 GitHub 匿名限流配额；缓存过期且网络失败时会明确报错并提示已知最新版本。
- **升级安全**：替换前自动把旧版备份为 `.bak`，并生成 `rollback.ps1` 回滚脚本 —— 新版本若无法启动，运行脚本即可退回。替换失败会自动还原备份。升级成功后自动清理残留下载包（每次升级不再累积 90MB+）。

### 已知边界：下载中断的 `.part` 残留

下载器的临时文件名是 `<目标名>.part-<时间戳>-<随机hex>`，而清理白名单
（`lib/temp-names.js` 的 `OWN_TEMP_PATTERNS`）里对应的规则是
`^hehe-.*\.part-\d+-[0-9a-f]+$` —— **只覆盖 `hehe-` 开头的目标名**。

这条边界**不是缺陷**，是刻意的保守设计：

- 取消/失败/重试耗尽时，下载器先释放网络读取器和文件句柄，再重试清理临时文件
  （Windows 上短暂占用可能导致 EPERM）。实测取消
  59MB 的 FFmpeg 下载不再残留。
- 因此只剩下**硬杀进程**（任务管理器结束、断电）这一类理论残留。
- 白名单不敢放宽成 `.*\.part-` 是有意的：`%TEMP%` 是全机器共享目录，
  别的程序的下载器也用 `.part` 后缀，放宽就会误删别人的文件。
  本项目对 `%TEMP%` 的清理原则是「只删能证明是自己产物的」。

如果将来真要覆盖任意目标名，正确做法是给下载临时文件加上
**可识别的前缀**（例如统一改成 `hehe-dl-<目标名>.part-<ts>-<hex>`），
而不是放宽正则。这条留待需要时再做。

### 已知边界：结构化错误只接线了两处

`lib/errors.js`（稳定错误码 + 建议操作 + 折叠的技术详情）机制已经完备并有单测，
但**实际调用点只有 2 处** IPC 处理器里的统一错误信封（`toPayload`）。
其余 handler 仍抛纯文本 `Error(中文语句)`，渲染层 toast 原文。

这是「机制先行、待铺开」，不是缺陷 —— 错误码的价值在于让界面能做程序化判断
（例如「磁盘满」时直接建议换目录），而把上百个 handler 逐个改写成结构化抛错
属于行为改动（文案会变），按本轮「不改用户可见行为」的约束没有铺开。
铺开时应当**分批**：先改高频失败路径（下载、压缩、转码、文件占用），
每批都附一条行为断言。
